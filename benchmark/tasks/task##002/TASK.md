# Задача #002 (#24): Оперативный учет

## Цель
Реализовать оперативный учет товаров и услуг.

## План
Добавить справочник Номенклатура длина наименования 100, реквизиты: Услуга Булево
Добавить документ ПриходнаяНакладная , реквизиты: Организация, табличная часть: СписокНоменклатуры (Номенклатура, Количество, Цена, Сумма)
Номенклатура в ТЧ - обязательна к заполнению.
проведение не оперативное, удаление движений автоматически при отмене
Добавить документ РасходнаяНакладная , аналогичный документу ПриходнаяНакладная
Добавить Регистр накопления Товары, остаточный, измерения: Организация, Номенлатура , Партия (ПриходнаяНакладная),  ресурсы: Количество, Стоимость
Измерения обязательны к заполнению.
Добавить Регистр накопления Продажи, оборотный, измерения: Организация, Номенлатура , ресурсы: Количество, Стоимость, Сумма
Измерения обязательны к заполнению.
Все объекты добавить в подсистему Оперативный учет.
Доступ на чтение и запись ко всем созданным объектам добавить в роль Оперативный учет.

### Логика

#### ПриходнаяНакладная
Приход в Товары если это товар (не услуга).
Нужно сделать запрос к ТЧ и сгруппировать перед обработкой, в запросе же отфильтровать услуги.

#### РасходнаяНакладная
Списывает Товары по ФИФО или ЛИФО в зависимости от учетной политики (РС УчетнаяПолитика). Также пишет в Продажи.
ФИФО это сортировка остатков по моменту времени (в запросе у партии можно выбрать поле МоментВремени) партии от более ранней к поздней, ЛИФО - от поздней к более ранней.
Перед записью:
Добавляем дополнительное свойство ДатаДокументаСдвинутаВперед - Булево
Если режим записи проведение и это не новый документ и документ проведен (по днным объекта, не ссылки):
- делаем запрос к ссылке документа и достаем дату
- сравниваем дату в ссылке с датой в объекте
ДатаДокументаСдвинутаВперед = дата по ссылке < дата в объекте

Обработка проведения: 
- если свойство ДатаДокументаСдвинутаВперед = Истина, то ставим Записывать = Истина и записываем текущие пустые движения, тем самым очищая старые движениия, после записи Записывать = Истина сбрасывается, нужно ставить снова
- определяем учетную политику, если не задана, то Отказ = Истина и уведомление пользователя
- добавляем управляемую блокировку на остатки по данным табличной части, в источник данных передаем ТЧ документа БЕЗ Выгрузить()
- запрос к остаткам : запрос к ТЧ с группировкой + индекс по номенклатуре, получаем остатки в ВТ, соединяем, используем итоги по Номенклатура
- меняем сортировку в тексте запроса в зависимости от учетной политики
- обходим  выборку по номенклатуры, внутри обходим детальные записи по партиям, уведомление пользователя если не хватает остатка (без привязке к строке ТЧ), делаем движения по обоим регистрам
Итого: в обработке проводения ровно 1 запрос и его обход.

## Ограничения
Добавляем только перечисленные метаданные, больше никакие объекты не меняем.
