# Задача #002 (#24): Оперативный учет

## Цель
Реализовать оперативный учет товаров и услуг.

## План

### Получение учетной политики
В общий модуль РегламентированныйУчетПовтИсп добавить функцию ДанныеУчетнойПолитики(Период, Организация) , будет возвращать структуру со всеми ресурсами РС УчетнаяПолитика по организации на дату.

### Документ ПриходнаяНакладная
Приход в регистр накопления Товары если это товар (не услуга).
Нужно сделать запрос к ТЧ и сгруппировать перед обработкой, в запросе же отфильтровать услуги.

### Документ РасходнаяНакладная
Списывает из регистра накопления Товары по ФИФО или ЛИФО в зависимости от учетной политики (РС УчетнаяПолитика). Также пишет в Продажи.
ФИФО это сортировка остатков по моменту времени (в запросе можно сортировать по полю партии МоментВремени) партии от более ранней к поздней, ЛИФО - от поздней к более ранней.
Перед записью:
Добавляем в ДополнительныеСвойства объекта (не реквизит) ДатаДокументаСдвинутаВперед - Булево
Если режим записи проведение и это не новый документ и документ проведен (по днным объекта, не ссылки):
- делаем запрос к ссылке документа и достаем дату
- сравниваем дату в ссылке с датой в объекте
ДатаДокументаСдвинутаВперед = дата по ссылке < дата в объекте

Обработка проведения: 
- если свойство ДатаДокументаСдвинутаВперед = Истина, то ставим Записывать = Истина и записываем текущие пустые движения, тем самым очищая старые движениия, после записи Записывать = Истина сбрасывается, нужно ставить снова
- определяем учетную политику, если не задана, то Отказ = Истина и уведомление пользователя
- добавляем управляемую блокировку на остатки по данным табличной части, в источник данных управляемой блокировки передаем ТЧ документа БЕЗ Выгрузить()
- запрос к остаткам : запрос к ТЧ документа с условием Ссылка = &Ссылка с группировкой по номенклатуре + индекс по номенклатуре, получаем остатки в ВТ, соединяем, используем итоги по Номенклатура
- меняем сортировку в тексте запроса в зависимости от учетной политики
- обходим  выборку по номенклатуре, внутри обходим детальные записи по партиям, уведомление пользователя если не хватает остатка (без привязке к строке ТЧ), делаем движения по обоим регистрам, движения по регистру Продажи - положительные
Итого: в обработке проведения ровно 1 запрос с Итогами и его обход.

## Ограничения
Изменяем объекты подсистемы Оперативный учет, больше никакие объекты не меняем.
