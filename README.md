# Agent Monitor — окружение ИИ-разработки на 1С

Платформа для разработки на 1С силами ИИ-агентов (Claude Code). Поднимает в проекте
готовое окружение из субагентов, навыков и правил работы с конфигурациями 1С, а
сверху даёт веб-приложение **AgentMon** — мониторинг и оркестрацию агентских
сессий: создание проектов и задач, очереди и стеки выполнения, справочник
MCP-серверов с разворачиванием в Docker.

## Быстрый старт

### Linux
```bash
./setup.sh      # venv, установка приложения, PostgreSQL в Docker (или SQLite), конфиг
./run.sh        # Web UI  →  http://127.0.0.1:8765
```

### Windows (PowerShell)
```powershell
powershell -ExecutionPolicy Bypass -File .\setup.ps1
powershell -ExecutionPolicy Bypass -File .\run.ps1
```

`setup` создаёт `.venv`, ставит приложение (`app`, editable) и зависимости, поднимает
PostgreSQL в Docker (если докер доступен; иначе использует локальный SQLite) и пишет
`.ai1c.env` с `AGENTMON_DSN`. `run` поднимает Web UI на `http://127.0.0.1:8765`.

Подробности и переменные окружения — в [docs/running-web-ui.md](docs/running-web-ui.md).
Фазы развития — в [docs/PHASES.md](docs/PHASES.md).

## Что внутри

Репозиторий состоит из трёх крупных частей:

| Каталог      | Назначение |
|--------------|------------|
| `app/`       | Приложение **AgentMon** — Python/FastAPI-бэкенд + статический web-фронтенд. Монитор и оркестратор агентских сессий, мастера проектов/задач, справочник MCP. |
| `template/`  | Шаблон разворачиваемого ИИ-окружения (`.claude/`): субагенты, навыки, правила, хуки, инструменты. Копируется в проект при его создании. |

Состояние
приложения (проекты, задачи, MCP-серверы, стеки выполнения) хранится в PostgreSQL
(или SQLite при отсутствии Docker).

## Реализованный функционал

### AgentMon — мониторинг и оркестрация агентов

- **Монитор сессий Claude Code**: статус, модель, токены, стоимость, текущая фаза.
  Приложение само держит агента в псевдотерминале (POSIX PTY / Windows ConPTY) и
  читает его JSONL-журналы, не полагаясь на внешний мультиплексор терминала.
- **Detached-раннер**: агенты запускаются отдельными процессами (`claude -p`),
  слежение ведётся по PID, коду выхода, JSONL и `task.json`. Устойчивость к
  перезапуску монитора: `running`-задачи при следующем старте возвращаются в очередь.
- **Бэкенды подключения**: `local` (PTY на этой машине) и `ssh` (PTY по SSH + чтение
  журналов по SFTP). Выбираются при добавлении проекта.
- **Расчёт стоимости** по токенам (`pricing.py`), подсчёт фазы и прогресса из журналов.

### Стартовая страница и панели

- **Стартовая страница** «Agent Monitor v.{версия}»: верхнее меню-справочники
  (Проекты, Задачи, MCP) и две панели.
- **Панель «Проекты и задачи»**: дерево проект → задачи с названием, путём, временем
  выполнения, статусом и этапом. Статусы: запланирована, в очереди, выполняется,
  остановлена, ожидает пользователя.
- **Панель «Выполнение»**: стеки выполнения — перетаскивание запланированных задач в
  стек, запуск/стоп/удаление стека (удаление срубает процесс), последовательное
  выполнение внутри стека, параллельные стеки, переупорядочивание в незапущенном стеке.

### Справочник «Проекты» и мастер создания

- **Одностраничный мастер** создания проекта: разделы Проект, Разработчик, Платформа,
  База, MCP, Модели агентов, Действия — на одной странице.
- **Валидации**: имя как python-идентификатор, пустой каталог, проверка доступа к
  базе 1С, проверка требований среды (Python и т.п.), лог разворачивания.
- **Карточка проекта**: имя и каталог неизменяемы; кнопка «обновить версию окружения»
  открывает мастер с предзаполненными полями; версия окружения хранится.
- Развёртывание окружения из `template/` в `.claude/` проекта плюс генерация
  `.mcp.json` / `docker-compose.mcp.yml`, выгрузка cf/cfe.

### Справочник «MCP» и разворачивание в Docker

Справочник под 7 видов MCP-серверов с полями и значениями по умолчанию; поле
«Подключение» формируется автоматически:

- **Произвольный**
- **Метаданные (http-сервис в 1С)** — «Скачать cfe» (`MCP_Сервер.cfe`)
- **Метаданные + произвольные запросы** — «Скачать cfe» (`1c-mcp-tools-1.0.6.cfe`)
- **Статический анализ BSL** — разворачивание контейнера только с BSL LS (без кодовой
  базы), создание `.bsl-language-server.json` с настройками проверок
- **Справка по платформе** (SSE)
- **1С:Напарник**
- **Индексированная кодовая база** (code-index)

Кнопка **«Развернуть в Docker локально»**: `POST /api/mcp/{id}/launch/stream` собирает
образ при отсутствии и запускает контейнер, **стримя лог сборки и запуска построчно**
(FastAPI `StreamingResponse`, UI дописывает лог в реальном времени). Сохранён и
блокирующий `POST /api/mcp/{id}/launch` (лог целиком). На Linux сборка идёт с
`--network=host`. Проверено вживую на `code-index` и `bsl-ls`.

### Система задач

- Структура `tasks/task#<id>/`: `task.json` + `TASK.md` + артефакты этапов
  (`ANALYZE.md`, `ARCHITECT.md`, `TESTS.md`, `DEVELOP.md`, `TESTING.md`, `REVIEW.md`,
  `DOCS.md`).
- **Мастер «Создать задачу»**: владелец-проект, поле «тесты» (обязательно при галке
  tests; testing недоступен без tests), кнопки «все / снять галочки», **гейты**
  (остановка и ожидание OK пользователя после выбранных этапов).
- **Статус-CLI** `task_status.py` и REST API управления этапами.
- **Циклический workflow** develop → [testing] → review → develop с архивированием
  артефактов и ограничением в 10 итераций.
- Тестовые задачи-заглушки (sleep → успех) для проверки стеков и монитора.

### Разворачиваемое ИИ-окружение (`template/`)

- **Субагенты** (`.claude/agents/`): analyst, architect, developer, tester, reviewer —
  с прописанными возможностями стандартных MCP и навыков.
- **Навыки** (`.claude/skills/`, 70+): работа с конфигурациями и расширениями 1С —
  метаданные, формы, роли, запросы, СКД, XDTO, макеты, веб-публикация,
  статанализ, ревью BSL, пакетные операции `1c-batch` и т.д.
- **Правила** (`.claude/rules/`): поиск перед написанием, артефакты задачи,
  жизненный цикл задачи, проверка статанализом через `bsl_ls`, запуск юнит-тестов,
  оптимизированная загрузка конфигурации, циклический review-workflow.
- **Хуки** (`.claude/hooks/`): `bsl_nudge.py` (подсказки при редактировании BSL),
  `route_to_orchestrator.py` (роутинг к оркестратору).
- **Инструменты** (`.claude/tools/`): `task_status.py`, `run-tests.py`,
  `load-config-optimized.py`.

Все правки содержимого окружения вносятся в `template/` — в одном месте; развёртывание
выполняет `agentmon.env.content.deploy_content`.

## Архитектура приложения (`app/src/agentmon/`)

- `registry.py` — реестр проектов, `queue.py` — очередь задач, `models.py` — модели.
- `backends/` — `local.py`, `ssh.py`, `factory.py` (выбор бэкенда по проекту).
- `pty_process.py` — интерактивный процесс в псевдотерминале.
- `jsonl_cursor.py` — инкрементальное чтение JSONL-журналов сессии.
- `observer.py` — снимок сессии (модель, токены, фаза, стоимость) из журналов.
- `monitor.py` — живые агенты по проектам, самоисцеляющийся кеш наблюдателей.
- `dispatcher.py` / `stack_dispatcher.py` — автоподача задач, возврат задач мёртвых
  агентов в очередь, выполнение стеков.
- `runner_detached.py`, `run_wrapper.py`, `run_store.py` — detached-раннер и учёт прогонов.
- `pricing.py` — расчёт стоимости по токенам; `version.py` — отпечаток исходников.
- `env/` — слой окружения: `installer.py`, `scaffold.py`, `content.py`,
  `project_api.py`, `task_api2.py`, `mcp_api.py`, `mcp_docker.py`,
  `mcp_docker_recipes.py`, `mcp_catalog.py`, `platform_dump.py`, `devbase.py`,
  `project_checks.py`, `migration.py` и схемы (`*_schema.py`).
- `store/` — слой БД: `db.py`, `schema.py`, `projects.py`, `tasks.py`, `stacks.py`,
  `mcp.py`, `runs.py`.
- `api.py` — FastAPI: REST + WebSocket; `__main__.py` — сборка зависимостей и запуск
  с фоновой петлёй диспетчера.
- `web/` — статический фронтенд (стартовая страница, грид сессий, мастера, справочники).

## Переменные окружения

| Переменная | Назначение | По умолчанию |
|------------|------------|--------------|
| `AGENTMON_HOST` | адрес прослушивания | `127.0.0.1` |
| `AGENTMON_PORT` | порт | `8765` |
| `AGENTMON_DSN` | DSN PostgreSQL (из `setup`) | — |
| `AGENTMON_DB` | путь к SQLite-реестру | `agentmon.db` |
| `AGENTMON_CLAUDE_CMD` | команда запуска агента | `claude --dangerously-skip-permissions .` |

## Требования

- **Python 3.10+**
- **Claude Code CLI** (`claude`) — для реального прогона агентов.
- **Docker** — для PostgreSQL и разворачивания MCP-серверов (для самого Web UI не нужен).
- На Windows — `pywinpty` (ставится автоматически с пакетом).

## Фазы развития

- **Фаза 0 — Прототип** (завершена): сквозной прототип на SQLite + файлах.
- **Фаза 1 — Продуктовый UI и модель данных** (завершена): PostgreSQL, стартовая
  страница и панели, справочники Проекты/Задачи/MCP, разворачивание MCP в Docker.
- **Фаза 2 — Бенчмарки**: оценка качества окружения на наборе тестовых заданий.
- **Фаза 3 — Удалённый доступ**: выполнение агентов/MCP по SSH и в Docker на удалённых хостах.

Подробности каждой фазы — в [docs/PHASES.md](docs/PHASES.md).
