# Циклический workflow: develop → [testing] → review → develop

Для задач, где требуется итеративное улучшение кода на основе результатов тестирования и замечаний ревьюера.

## Включение циклического workflow

Циклический workflow **активируется автоматически**, если включены этапы:
- `testing: true` И/ИЛИ `review: true`

При этом:
- Если `testing` включен и не пройдён → цикл: develop → testing → develop
- Если `testing` включен и пройдён → цикл: develop → testing → review → develop
- Если `testing` отключен, но `review` включен → цикл: develop → review → develop

## Логика выполнения

### 1. Этап `testing` (если включен)
```
После завершения testing:
├─ Если TESTING.md содержит "✗" (тесты не пройдены):
│  ├─ Инкрементировать счётчик итераций
│  ├─ Если итерации < 10: перезагрузить develop в pending
│  └─ Если итерации ≥ 10: отметить testing как failed, остановиться
└─ Если TESTING.md содержит "✓" (все тесты пройдены):
   └─ Перейти к review
```

### 2. Этап `review` (если включен)
```
После завершения review:
├─ Если REVIEW.md содержит "✗" (проблемы обнаружены):
│  ├─ Инкрементировать счётчик итераций
│  ├─ Если итерации < 10:
│  │  ├─ Если testing включен: перезагрузить testing в pending
│  │  └─ Если testing отключен: перезагрузить develop в pending
│  └─ Если итерации ≥ 10: отметить review как failed, остановиться
└─ Если REVIEW.md содержит "✓" (одобрено):
   └─ Перейти к следующему этапу (testing или docs)
```

## Управление счётчиком итераций

Счётчик хранится в файле `.iteration_count` в каталоге задачи (не в task.json):

```bash
# Получить текущий счётчик
cat tasks/task#001/.iteration_count

# Поле счётчика содержит число итераций (0 = первый запуск)
# Максимум: 10 итераций
```

## Архивирование артефактов при циклах

Перед новой итерацией артефакты переименовываются для сохранения истории:

```bash
# Пример: если это итерация 2, то:
# DEVELOP.md → DEVELOP.1.md (старый)
# TESTING.md → TESTING.1.md (старый)
# REVIEW.md → REVIEW.1.md (старый)
# 
# Новые артефакты будут созданы как DEVELOP.md, TESTING.md, REVIEW.md
```

## Остановка цикла

Цикл останавливается:
- ✅ **Одобрения ревьюером** (вердикт "ПРИНЯТО" в REVIEW.md)
- ❌ **Достижения максимума итераций** (iteration_count ≥ 10) → этап отмечается `failed`
- ❌ **Явной остановки** командой `python3 .claude/tools/task_status.py <task_dir> <stage> failed`

## Примечания

- Счётчик итераций начинается с 0 и хранится в `.iteration_count`
- Максимум 10 итераций предотвращает бесконечные циклы
- Каждый раз при возврате в develop обновляется DEVELOP.md с указанием номера итерации
- История всех версий сохраняется через архивные файлы (DEVELOP.1.md, DEVELOP.2.md и т.д.)
- Разработчик видит номер итерации в артефактах
- Ревьюер/тестер может давать замечания в каждой итерации
