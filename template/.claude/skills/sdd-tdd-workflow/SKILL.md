# SDD + TDD

## Спецификация до кода (SDD)
Для новой функциональности и значимых изменений сначала спека (цель, требования,
критерии приёмки), затем техдизайн, только потом код.

## Тесты до реализации (TDD)
1. **Red** — разработчик тестов (субагент `developer-tests`) пишет юнит-тесты средствами, принятыми в проекте, по критериям приёмки; они падают (этап «написание тестов»).
2. **Green** — разработчик (субагент `developer`) пишет минимальный код, доводит тесты до прохождения.
3. **Проверка** — на этапе «тестирование» прогон тестов и вердикт ведёт оркестратор (субагента-тестировщика нет); при падении возвращает задачу на разработку, где разработчик (`developer`) разбирает лог прогона и чинит код.

## Слои тестов
- Выбор тест-раннера — на усмотрение проекта/задачи.
- Прогоняй статический анализ (MCP `bsl_ls`, инструмент `mcp__bsl_ls__check`) на каждом шаге.

## Цикл задачи
анализ → план → написание тестов → разработка → тестирование → ревью → документация.
