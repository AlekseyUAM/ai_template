# Удаление движений

Режим удаления движений документа задаётся свойством «Удаление движений» (в XML-выгрузке —
`<RegisterRecordsDeletion>`). Значение свойства у документа — в `code_index`. Режим влияет
на реализацию проведения, на то, когда удаляются старые движения, и на длительность блокировок.

## 3 вида удаления движений

### 1. Удалять автоматически (`AutoDelete`)

Платформа удаляет старые движения **в начале** транзакции проведения (и при перепроведении),
ещё до `ОбработкаПроведения`.

- Реализация: чистить движения вручную не нужно; `Движения.<Регистр>.Очистить()` избыточен.
- Блокировки: удаление в начале транзакции → таблицы движений блокируются рано и на всю
  транзакцию. Самый «тяжёлый» режим; при массовом перепроведении в цикле эффект
  мультипликативен (N ранних исключительных блокировок).

### 2. Удалять автоматически при отмене проведения (`AutoDeleteOnUnpost`) — рекомендуемый

При **отмене** проведения платформа сама удаляет движения. При **проведении**
автоматического удаления нет — старые движения перезаписываются новыми записями при записи набора с замещением.

- Реализация: старые движения затираются новыми при записи набора с замещением. Для
  затирания при перепроведении **не нужно** явно вызывать `Движения.Записать()` — достаточно
  установить `Движения.<Регистр>.Записывать = Истина;`, и проведение само запишет все наборы
  с `Записывать = Истина` (старые движения перезапишутся новыми). Явная очистка + запись нужна
  лишь в особых случаях — например, при переносе даты документа вперёд, когда старые движения
  не должны попасть в запрос остатков внутри проведения: тогда сначала
  `Движения.<Регистр>.Очистить()`, затем `Движения.Записать()`, чтобы удаление стало видно
  последующему запросу в той же транзакции.
- Блокировки: движения записываются/затираются в момент записи набора (проведением или явным
  `Записать()`) — ближе к концу транзакции → короче блокировки, выше параллельность.

### 3. Не удалять автоматически (`DontAutoDelete`)

Платформа не удаляет движения ни при проведении, ни при отмене — всё на разработчике.

- Реализация: нужен, когда движения формируются не только проведением (ручная корректировка,
  частичное обновление наборов, движения нескольких документов в одном наборе).
- Блокировки: полностью определяются логикой кода.

## Зачем нужны, отличия

- **По реализации**: при `AutoDelete` ручная очистка/запись не требуется. При
  `AutoDeleteOnUnpost` достаточно установить `Движения.<Регистр>.Записывать = Истина` —
  проведение само запишет наборы, старые движения перезапишутся новыми; явная
  `Движения.Записать()` нужна лишь чтобы убрать старые движения из поля зрения запроса внутри
  проведения (например, при переносе даты вперёд: `Очистить()` + `Записать()`). При
  `DontAutoDelete` удаление и запись движений полностью на разработчике.
- **По блокировкам**: `AutoDelete` удаляет (и блокирует) движения в начале транзакции →
  блокировки держатся дольше; `AutoDeleteOnUnpost` — ближе к концу → короче. Для снижения
  времени блокировок предпочтителен `AutoDeleteOnUnpost`.
- **Особенность флага «Записывать»**: `Движения.Записать()` (без имени регистра) записывает
  все изменённые наборы и **снимает** флаг `Записывать`; `Движения.<Регистр>.Записать()`
  записывает один набор и флаг **не снимает**.
- **Отмена проведения с ручной корректировкой**: для документов, где движения правятся
  вручную, при отмене проведения отключать активность движений, а не удалять записи
  (см. в `bsl-coding-standards` раздел «Активность движений»).

## Типичные ошибки (сигналы для ревью)

- `Движения.<Регистр>.Очистить()` в `ОбработкаПроведения` при режиме `AutoDelete` (избыточно).
- Движения пишутся, но не задан `Движения.<Регистр>.Записывать = Истина` → при перепроведении
  старые движения не затираются.
- `AutoDelete` на документе с тяжёлым проведением / массовым перепроведением (длинные блокировки).
- Перепроведение документов в цикле (мультипликативные блокировки).

Порядок записи регистров и блокировки — см. [Методика контроля остатков](balance-control-methodology.md)
и [Блокировки](locks.md).
