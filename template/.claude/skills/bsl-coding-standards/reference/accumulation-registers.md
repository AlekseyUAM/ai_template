# Регистры накопления: хранение, виртуальные таблицы и агрегаты

Справка для проектирования запросов и отчётов по регистрам накопления. Проверки ниже
ручные: структура запроса и семантика задачи не выводятся из XML автоматически.
Severity как в остальных справках: `[критичная]` = error, `[важная]` = warning,
`[минорная]` = info. Находка наследует severity своего пункта.

## Как устроен регистр

- Движения хранятся в отдельной таблице. У регистра вида **«Остатки»** есть поле
  «ВидДвижения» (приход/расход), у вида **«Обороты»** его нет: приход пишется плюсом,
  расход — минусом.
- Итоги: у вида «Остатки» — таблица остатков, у вида «Обороты» — таблица оборотов.
  Итоги ведутся помесячно (и, для остатков, дополнительно на текущую дату). Поле
  `_Splitter` — разделение итогов для параллельной записи.
- Виртуальные таблицы (ВТ) в базе не хранятся: платформа строит SQL по переданным
  параметрам и настройкам итогов регистра.
- ВТ **«Обороты»** доступна у обоих видов. У вида «Остатки» она читает таблицу движений;
  у вида «Обороты» — итоги оборотов и только нерассчитанный период берёт из движений.
- ВТ **«Остатки»** и **«Остатки и обороты»** доступны только у вида «Остатки». Если
  использование итогов отключено, ВТ «Остатки» не работает.

## Что возвращают виртуальные таблицы

| ВТ | Состав результата | Особенности |
|---|---|---|
| `Обороты(НачалоПериода, КонецПериода, Периодичность, Условие)` | одна строка на комбинацию измерений (и период, если задана периодичность); для каждого ресурса — `РесурсОборот`, а у регистра вида «Остатки» ещё `РесурсПриход`/`РесурсРасход` | **уже сгруппирована**: обороты по измерениям посчитаны платформой |
| `Остатки(Период, Условие)` | одна строка на комбинацию измерений; для каждого ресурса — `РесурсОстаток` | верхняя граница периода обрабатывается как `< Период`; движение ровно в эту секунду не попадёт |
| `ОстаткиИОбороты(...)` | начальный остаток, приход, расход, оборот, конечный остаток | самая тяжёлая ВТ: соединяет движения за период с остатками; на длинном периоде читает большой объём движений |

Если задана периодичность, в результате появляются поля `ПериодДень`, `ПериодМесяц`
и т.п., а группировка выполняется по периоду и измерениям. Это тоже работа ВТ, а не
повод добавлять свой `СГРУППИРОВАТЬ ПО`.

## Запросы к регистрам накопления

- [важная] **Не добавляй `СГРУППИРОВАТЬ ПО` к выборке из ВТ «Обороты»/«Остатки».** ВТ уже
  агрегирует ресурсы по измерениям (и периоду). Группировка по всем полям ВТ — лишняя
  работа и признак непонимания модели. `СГРУППИРОВАТЬ ПО` допустима только если
  соединение/выражение действительно размножает строки; тогда группируй по добавленному
  полю, а не по всему составу ВТ.
- [важная] **Отборы по измерениям — в параметрах ВТ, а не в `ГДЕ` после неё.** Условие
  `Организация = &Организация` передаётся четвёртым параметром ВТ: платформа встраивает
  его в SQL и использует индексы/итоги. Условие в `ГДЕ` применяется уже после выборки
  всей ВТ и может читать лишние данные.
- [важная] **Верхняя граница периода.** У ВТ «Обороты» конец периода включающий; у ВТ
  «Остатки» — исключающий (`<`), поэтому для остатков на конец дня/секунды передавай
  границу следующего момента (например, `ДОБАВИТЬКДАТЕ(КОНЕЦПЕРИОДА(&Дата, ДЕНЬ), СЕКУНДА, 1)`).
  Не смешивай `МоментВремени`/`Граница` с параметрами ВТ — туда передаются значения.
- [критичная] **Не используй физическую таблицу регистра там, где нужна ВТ.** Прямая
  таблица движений не учитывает итоги и требует явного `Активность = Истина`; ВТ
  учитывает активность сама и умеет брать итоги. Прямая таблица уместна только для
  служебных задач (например, полный проход по движениям), и тогда условие активности
  обязательно.
- [важная] **«Остатки и обороты» — не для длинных периодов.** ВТ читает движения за весь
  период и соединяет их с остатками. Если нужны только обороты — бери «Обороты»; если
  только остаток — «Остатки». Для отчёта за год «Остатки и обороты» может стать узким
  местом.
- [важная] **Не выводи лишние поля «на всякий случай».** Каждое поле в запросе/наборе
  данных должно быть нужно отчёту или вычислению. Поля и соединения сверх ТЗ — повод
  для открытого вопроса, а не для самовольного расширения модели.
- [важная] **Не читай регистратор «через точку».** Отчёт по регистру не должен
  разыменовывать `Регистратор.Реквизит`: это неявное соединение, а в РИБ регистратора
  может не быть. Нужные данные должны быть в измерениях/ресурсах/реквизитах регистра.
- [минорная] **Порядок измерений и индексы.** Измерения входят в индексы в порядке
  конфигуратора; индекс работает, когда отбор начинается с ведущих измерений. Учитывай
  это при проектировании регистра и запроса.

## Агрегаты оборотных регистров

- [важная] **Агрегаты — только по обоснованной производительности.** Это отдельные
  таблицы с собственной периодичностью и составом измерений; их нужно включать и
  перестраивать вручную (`РегистрыНакопления.<Регистр>.ОбновитьАгрегаты()`), в отличие
  от итогов, которые платформа поддерживает автоматически.
- [важная] **Агрегат помогает только при совпадении состава измерений и периодичности
  запроса.** Если в агрегате нет измерения, по которому строится отчёт, платформа его
  не использует и запрос может стать медленнее.
- [минорная] **Сначала измерь.** Агрегаты имеют смысл на сотнях тысяч/миллионах записей
  и при доказанной проблеме производительности; для малых регистров это лишняя
  инфраструктура.

## Проведение документов по регистрам накопления

Справка охватывает типовые грабли проведения; метаданные конкретного регистра бери из
`code_index` (вид регистра, ресурсы, измерения, обязательность заполнения, режим удаления
движений).

### Заполнение движений

- [критичная] **`Период` заполняется в каждой записи движения.** При проведении платформа
  его не подставляет: незаполненный период приводит к ошибке
  «Запись неверна! Период не может быть пустым!». Пиши `Движение.Период = Дата;`
  (или дату, требуемую бизнес-логикой) для каждого `Движения.<Регистр>.Добавить()`.
- Для регистра вида **«Остатки»** заполняется `ВидДвижения` (`Приход`/`Расход`);
  у оборотного регистра `ВидДвижения` нет — ресурсы пишутся со знаком (расход — минус).
- [важная] **Знак ресурса.** Ресурсы, по которым формируются отрицательные движения
  (расход, списание), должны иметь в метаданных `AllowedSign = Any`; с `Nonnegative`
  платформа отклонит запись отрицательного движения.
- Ресурс в движении — это значение по смыслу ТЗ (стоимость партии, сумма продажи,
  количество), а не «на всякий случай» рассчитанная величина. Не добавляй распределения
  и пересчёты, которых нет в ТЗ.
- [критичная] **Не сохраняй объект выборки.** `Партии.Добавить(Выборка)` добавляет сам
  объект `ВыборкаИзРезультатаЗапроса`, который платформа переиспользует на каждом
  `Следующий()` — все элементы массива указывают на последнюю строку. Копируй поля в
  `Структура`/`ТаблицаЗначений` или обходи вложенную выборку (см. ниже).

### Запись движений и чтение в транзакции

- `Движения.<Регистр>.Записывать = Истина` — набор будет записан платформой после
  `ОбработкаПроведения` (до завершения транзакции).
- Чтобы **прочитать свои движения запросом внутри процедуры** (контроль остатков,
  перепроведение), нужен явный `Движения.<Регистр>.Записать()`: запрос не видит набор,
  существующий только в памяти.
- После явного `Движения.Записать()` флаг `Записывать` сбрасывается — для автоматической
  записи последующих движений выставь его заново.
- [важная] Повторный `Движения.Записать()` — ресурсоёмкая операция с блокировками;
  вызывай только когда действительно нужно прочитать движения в той же транзакции.
- Удаление движений при отмене проведения — свойство документа
  `RegisterRecordsDeletion = AutoDeleteOnUnpost`; при перепроведении старые движения
  замещаются записью выбранных наборов (`RegisterRecordsWritingOnPost`).

### Построение отбора и обход результата

- [важная] **Отбирай остатки по данным документа в параметрах ВТ**, а не читай все
  остатки организации с фильтрацией после соединения:
  `Номенклатура В (ВЫБРАТЬ ... ИЗ <ТЧ документа> ГДЕ НЕ Услуга)`.
- [важная] **Группировка — средствами запроса:** `ИТОГИ ПО <измерение>` и обход
  `Результат.Выбрать(ОбходРезультатаЗапроса.ПоГруппировкам)`; внутри группировки —
  вложенная выборка (`ВыборкаПоНоменклатуре.Выбрать()`). Это короче и надёжнее ручной
  группировки с массивами копий строк.
- [важная] **Услуги и прочие несписываемые строки** обрабатывай в том же обходе по флагу,
  посчитанному запросом (`МАКСИМУМ(<Реквизит>)`), а не вторым проходом по ТЧ.
- [важная] **`УПОРЯДОЧИТЬ ПО`** — только самостоятельные псевдонимы. Не оборачивай
  псевдоним в функцию (`ЕСТЬNULL(ДатаПартии, ...)` даёт «Поле не найдено»): сортировка
  должна идти по колонке результата.
- [важная] **Сортировка партий по моменту** — `Партия.МоментВремени` (ФИФО/ЛИФО),
  без соединения с документом ради даты; подробнее — в
  [Граница и момент времени](boundary-and-moment.md).
- [важная] **Соединение с виртуальной таблицей** — через материализацию
  (`ПОМЕСТИТЬ <ВТ>` + `ИНДЕКСИРОВАТЬ ПО`), а не прямым соединением с ВТ.
- [минорная] **Один запрос на проведение.** Дополнительные чтения (учётная политика,
  дата по ссылке) допустимы, но не в цикле и не вместо одного агрегирующего запроса.
- [критичная] **Прикладной отказ — не исключение.** В `ОбработкаПроведения` недостаток
  остатка/отсутствие настроек — это `Отказ = Истина` + `ОбщегоНазначения.СообщитьПользователю`;
  `ВызватьИсключение` прерывает транзакцию нештатно и лишает пользователя сообщения.

### Чек-лист проведения

- [ ] `Период` заполнен в каждом движении.
- [ ] `AllowedSign` ресурсов соответствует знаку движений.
- [ ] Нет сохранения объектов `Выборка` в массивах/структурах.
- [ ] Остатки отбираются по данным ТЧ в параметрах ВТ.
- [ ] Группировка и обход — `ИТОГИ` + `ОбходРезультатаЗапроса.ПоГруппировкам`, вложенная выборка.
- [ ] `УПОРЯДОЧИТЬ ПО` — без функций от псевдонимов; партии — по `МоментВремени`.
- [ ] Блокировка остатков взята до чтения (см. [Блокировки](locks.md)).
- [ ] Прикладные отказы — `Отказ` + сообщение, не исключение.
- [ ] Старые движения очищены/замещены при перепроведении и сдвиге даты.

## Чеклист перед сдачей запроса/отчёта

- [ ] Источник — ВТ, а не физическая таблица движений (если нет особой причины).
- [ ] Отборы по измерениям стоят в параметрах ВТ.
- [ ] Нет `СГРУППИРОВАТЬ ПО` по полям ВТ без обоснования.
- [ ] Верхняя граница периода корректна для выбранной ВТ.
- [ ] В запросе нет полей/соединений сверх ТЗ; каждое поле используется.
- [ ] Для длинного периода не используется «Остатки и обороты» без необходимости.
- [ ] Нет разыменования регистратора «через точку».
- [ ] Если применены агрегаты — они действительно нужны и обновляются регламентно.
