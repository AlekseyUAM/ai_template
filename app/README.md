# Agent Monitor

Веб-монитор и оркестратор сессий Claude Code, работающих локально или на
удалённом сервере. Показывает запущенные сессии (статус, модель, токены,
стоимость, текущая фаза), даёт чат с сессией, очередь задач по проекту с
автоподачей следующей и стоп/резюм.
Монитор сам держит агента в псевдотерминале (локально или по SSH) и читает
его JSONL-журналы, не полагаясь на внешний мультиплексор терминала.

## Требования

- Python 3.10+
- На Windows дополнительно требуется `pywinpty` — ставится автоматически
  вместе с пакетом, отдельно ничего устанавливать не нужно.
- Внешний терминальный мультиплексор ставить не нужно: монитор сам держит
  агента в псевдотерминале.

## Установка и запуск

```bash
cd agent-monitor
pip install -e .            # ставит пакет agentmon и зависимости
python -m agentmon          # сервер на http://127.0.0.1:8765
```

Без установки можно запустить напрямую:

```bash
PYTHONPATH=src python -m agentmon
```

Открыть в браузере: `http://127.0.0.1:8765`. Если монитор запущен на другой
машине — пробросить порт по SSH с клиента:

```bash
ssh -L 8765:127.0.0.1:8765 user@server
# затем открыть http://127.0.0.1:8765
```

## Бэкенды

Каждый проект работает через один из двух бэкендов, выбирается при
добавлении проекта:

| Бэкенд  | Где живёт проект           | Как запускается агент                                      |
|---------|-----------------------------|--------------------------------------------------------------|
| `local` | каталог на этой же машине   | псевдотерминал (PTY) в процессе монитора                     |
| `ssh`   | каталог на удалённом хосте  | канал SSH с PTY; журналы читаются по SFTP                    |

Параметры подключения (хост, пользователь, порт и т.п.) задаются на странице
«Проекты» при добавлении или редактировании проекта. Аутентификация — по
ключу или через ssh-agent; пароль в открытом виде монитор не хранит.

## Проекты

Проекты добавляются на странице «Проекты» в браузере и хранятся в SQLite
(путь задаётся переменной окружения `AGENTMON_DB`, по умолчанию
`agentmon.db`). Реестр проектов и очередь задач переживают перезапуск
браузера и перезапуск компьютера — это серверное состояние, а не состояние
вкладки.

## Важное ограничение

Агенты живут внутри процесса монитора: при его остановке (перезапуск,
падение, `Ctrl+C`) все запущенные агенты завершаются вместе с ним. Задачи,
которые были в статусе `running` в момент остановки, при следующем запуске
монитора автоматически возвращаются в очередь — считать, что они выполнены,
нельзя, но и потерять их тоже нельзя.

## Windows

Путь проекта указывается в родном для Windows виде (например
`C:\work\demo`). Соответствие между JSONL-журналами `claude` и проектами
монитор определяет по полю `cwd` внутри самого журнала, а пути перед
сравнением нормализует: слэши приводятся к одному виду, хвостовой слэш
отбрасывается, а путь с буквой диска сравнивается без учёта регистра.
Поэтому смешение слэшей и регистр диска сопоставлению не мешают.

## Приватность

Аватарки агентов в гриде сессий рисует внешний сервис `api.dicebear.com`:
на каждую отрисовку туда уходит путь проекта — он передаётся в адресе
картинки как seed. Если это нежелательно, аватарки отключаются правкой
`avatarUrl` в `web/app.js`.

## Прогон в Docker (Debian)

Поднять Debian-контейнер с python, реальным `claude` и заглушкой `claude-fake`:

```bash
cd agent-monitor
docker compose build
docker compose up -d
docker compose exec agentmon bash        # зайти внутрь
```

Внутри контейнера:

```bash
mkdir -p /root/projects/test1            # создать проект
python -m agentmon                       # сервер на 0.0.0.0:8765
```

С хоста открыть в браузере: `http://127.0.0.1:8765` (порт проброшен из контейнера).
На странице «Проекты» добавить проект с путём внутри контейнера (например
`/root/projects/test1`), бэкенд `local`, запустить агента, добавлять задачи в очередь, писать в чат.

По умолчанию агент — это `claude-fake` (заглушка, **0 токенов**): пишет реалистичные
`~/.claude/projects/*.jsonl` (модель, токены, фаза) и отвечает в терминал.

### Боевой прогон на реальном claude

Реальный `claude` CLI уже установлен в образе. Шаги:

1. **Авторизоваться внутри контейнера** (делается один раз — `~/.claude` изолирован и
   сохраняется в volume, переживает перезапуск):

   ```bash
   docker compose exec agentmon bash
   claude            # интерактивно -> /login: откроется URL,
                     # открой его в браузере хоста, подтверди, вставь код обратно
   # проверка:
   claude -p "привет"
   ```

   Альтернатива — API-ключ: добавь в `docker-compose.yml` env `ANTHROPIC_API_KEY: "sk-ant-…"`
   и `docker compose up -d`.

2. **Переключить монитор на реальный агент**: в `docker-compose.yml` поменяй
   `AGENTMON_CLAUDE_CMD` на `"claude --dangerously-skip-permissions ."`, затем
   `docker compose up -d`.

`IS_SANDBOX=1` в compose уже выставлен — без него `claude --dangerously-skip-permissions`
отказывается работать под root в контейнере.

Сброс до чистого состояния (удалит и авторизацию): `docker compose down -v && docker compose up -d`.

## Архитектура

- `registry.py` — реестр проектов в SQLite (CRUD, уникальность по бэкенду/хосту/пути).
- `queue.py` — очередь задач по проекту (SQLite), возврат «осиротевших» running-задач.
- `backends/` — бэкенды подключения: `local.py` (PTY на этой машине), `ssh.py`
  (PTY по SSH + SFTP для журналов), `factory.py` — выбор бэкенда по проекту.
- `pty_process.py` — интерактивный процесс в псевдотерминале (POSIX pty / Windows ConPTY).
- `jsonl_cursor.py` — инкрементальное чтение JSONL-журналов сессии.
- `observer.py` — сборка снимка сессии (модель, токены, фаза, стоимость) из журналов.
- `monitor.py` — живые агенты по проектам, снимки сессий, самоисцеляющийся кеш наблюдателей.
- `dispatcher.py` — автоподача следующей задачи, возврат задач мёртвых агентов в очередь.
- `api.py` — FastAPI: REST + WebSocket.
- `__main__.py` — сборка зависимостей и запуск сервера с фоновой петлёй диспетчера.
- `web/` — статический фронтенд (страница проектов, грид сессий, чат, очередь).
