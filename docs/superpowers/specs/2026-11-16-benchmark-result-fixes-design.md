## 1. Цель

Устранить в шаблоне (`template/`), MCP-сервере `bsl_ls` (`app/`) и benchmark-метриках
(`benchmark/`) причины, которые в прогоне task##001–002 дали дорогой диагностический

итераций в `task.json` и нежелательный сбор токенов/стоимости.

## 2. Scope

### Делаем

1. Справочник по секции `ИТОГИ` в `bsl-coding-standards/reference` + ссылки для
   обнаруживаемости.
2. Политика комментариев: в телах методов и внутри текста запросов не пишем;
   допустимы заголовок модуля и описание метода перед объявлением; существующие
   комментарии не удаляем. Из `query-review` убираются требования писать
   комментарии в коде; обоснования исключений переносятся в waiver-таблицу
   `DEVELOP.md`.
3. `query-analyze`: `totals-field-not-aggregated` → `error`; `extract_queries.py`
   срезает ведущие `//`-строки и громко предупреждает/падает при `Запрос.Текст`
   без извлечённых запросов.
4. `code-analyze`: числовые аккумуляторы не считаются строковой конкатенацией;
   новое консервативное правило `use-before-assignment`.
5. `task_status.py`: `done` только из `running`, запрет повторного `running`,
   команда `restart`, корректные `iteration`/`runs`.
6. `bsl_ls`: обязательный `sha256` (или `file_path`, если сервер видит файл);
   `REVIEW.md` — обязательная таблица сырых счётчиков анализаторов.
7. Benchmark-метрики: убрать токены/стоимость; искать логи по identifier/папке;
   учитывать прогоны и правки субагентов.
8. `pkill -f "1cv8 ENTERPRISE"` запрещён в промптах; безопасный вариант `[1]cv8`.
9. Waiver-таблица в `DEVELOP.md` и её проверка ревьюером.

### Не делаем

- runtime-probe в `1c-batch/run-tests.py`;
- материализацию `ВТОстатки` и вынос 207-строчного метода;
- полный `task.diff` с `src/cfe/**` и `configs/**`;
- `validate_query` для многострочных литералов с `|`;
- автоматическое правило `code-analyze` про комментарии (по решению пользователя —
  только инструкция разработчику и чистка требований из `query-review`).

Содержание (на основе документов из `/home/uam/projects/ai_template/tmp/docs/Итоги в запросах/`):

1. Назначение `ИТОГИ`: итоговые строки **добавляются** к детальным, в отличие от
   `СГРУППИРОВАТЬ ПО`, которое сворачивает строки.
2. Синтаксис:
   `ИТОГИ [агрегаты] ПО [ОБЩИЕ,] Группировка1[, Группировка2…]`,
   `ИЕРАРХИЯ` / `ТОЛЬКО ИЕРАРХИЯ`, порядок уровней.
3. Агрегаты: `СУММА`, `КОЛИЧЕСТВО`, `КОЛИЧЕСТВО РАЗЛИЧНЫЕ`, `МАКСИМУМ`,
   `МИНИМУМ`, `СРЕДНЕЕ`.
4. **Ключевое правило**: на строке итогов доступны только поля, входящие в
   группировку `ИТОГИ`, и агрегаты. Остальные поля возвращаются как `NULL`
   (в BSL — `Неопределено` после преобразования). Отсюда runtime-ошибки вида
   «Преобразование значения к типу Булево не может быть выполнено» при обходе
   итогов. Лечение: агрегировать поле в `ИТОГИ` или убрать его из выборки.
5. `ОБЩИЕ`: корневая итоговая запись по всей выборке.
6. Несколько группировок: каждый уровень обходится отдельной вложенной выборкой.
7. Произвольные выражения в итогах: псевдоним обязателен, поля должны быть в
   списке выборки, вне агрегатов допустимы только группировочные поля;
   поля «ещё не полученных» группировок равны `NULL`.
8. Итоги по набору полей: `АВТОНОМЕРЗАПИСИ` как идентификатор набора и одна
   группировка вместо матрёшки циклов.
9. Обход результата в BSL:
   `Результат.Выбрать(ОбходРезультатаЗапроса.ПоГруппировкам)`,
   `Выборка.Следующий()`, `Выборка.Выбрать(ОбходРезультатаЗапроса.Прямой)`,
   явное имя группировки вторым параметром; `ОБЩИЕ` добавляет верхний уровень.
10. Типичные ошибки: неагрегированные поля; `УПОРЯДОЧИТЬ ПО` после `ИТОГИ`;
    обход деталей вместо групп; потеря уровней при `ОБЩИЕ`; `ИТОГИ` в запросе
    СКД (запрещено — у СКД своя агрегация).
11. Примеры: текст запроса и BSL-обход.
12. Источники: названия и URL статей (chel1c.ru, infostart.ru, aether-lab.ru,
    confaster.ru, helpme1s.ru, статья ИТС «Использование произвольных выражений
    в итогах языка запроса»).

   - сообщение: переменная останется `Неопределено`, если условие не выполнится;
     инициализировать до ветвления;
   - консервативность: параметры, `Перем`, переменные циклов, повторные
     присваивания и наличие любой ветки `Иначе` исключают находку.

### 4.7. `bsl_ls`

`app/docker/mcp/bsl_check_server.py`:

- `run_check(..., expected_sha256=None)`:
  - нормализует и проверяет `sha256` (64 hex);
  - если `expected_sha256` передан и не совпал с хэшем `code` — `ok=False`,
    `summary` с обоими хэшами, java не запускается;
  - в результат добавляет `sha256`, `bytes`, `counts`
    (`Error`/`Warning`/`Information`/`Hint`);
- инструмент `check(sha256: str, code: str | None = None, file_path: str | None = None, config=..., filename=...)`:
  - `sha256` обязателен всегда;
  - ровно один источник: `code` или `file_path`;
  - `file_path` читается сервером; если файл недоступен — понятная ошибка
    (Docker без монтирования → передайте `code`+`sha256`);
  - `filename` по умолчанию — basename `file_path` или `Module.bsl`;
  - ответ `{ok, count, counts, diagnostics, summary, sha256, source, bytes}`;
- обновить docstring и комментарий Dockerfile: сервер по-прежнему stateless;
  `file_path` работает только при видимом пути.

### 4.9. `pkill`

`template/.claude/agents/developer.md` и `developer-tests.md` — в «Границы»:

- никогда не `pkill -f "1cv8 ENTERPRISE"` — шаблон матчит собственную командную
  строку, убивает shell (код 144) и может задеть чужие сеансы;
- безопасно: `pkill -f '[1]cv8'`, `pgrep -f '[1]cv8'` + точечный `kill <pid>`;
- предпочитать `run-tests.py`/`1c-batch` (убивают только своё дерево процессов).

`task-orchestration` уже содержит этот раздел — не дублировать, достаточно
ссылки.

## 6. Критерии приёмки

1. Все перечисленные тесты зелёные.
2. `git status` после коммита чистый; коммиты — локально в `main`, без push.
3. В `metrics.json`/digest больше нет `usage`, `cost_usd`, `cost=`.
4. `REVIEW.md`-шаблон требует таблицу сырых counts; `reviewer.md` ссылается на
   неё.
5. `DEVELOP.md`-шаблон требует waiver-таблицу с пятью колонками.
6. Справочник `query-totals.md` существует и доступен по ссылкам из
   `bsl-coding-standards`, `developer.md`, `query-review`, `query-analyze`.
7. В `query-review` не осталось требований писать комментарии в коде/запросе.
8. `totals-field-not-aggregated` печатается как `error`.
9. `extract_queries.py` извлекает запрос с ведущими `//` и предупреждает при
   нулевом извлечении.
10. `task_status.py` не даёт `done` без `running`, поддерживает `restart`,
    `runs`/`iteration` согласованы.
11. `bsl_ls.check` без `sha256` отклоняется; при несовпадении хэша java не
    запускается.
12. `pkill -f "1cv8 ENTERPRISE"` запрещён в промптах разработчика и
    тест-разработчика.

## 7. Риски и меры

| Риск | Мера |
|---|---|
| Обязательный `sha256` ломает старых агентов/внешние вызовы | Обновить все промпты, `mcp-usage`, `verify-with-syntax-checker`, `bsl_nudge`, `docs/mcp/bsl-ls.md`; явная ошибка с примером |
| `use-before-assignment` даёт ложные срабатывания | Консервативная эвристика: ровно одно присваивание, нет `Иначе`, не параметр/`Перем`/цикл |
| Строгий `task_status` ломает старые сценарии | Обновить `cyclic-review-workflow`, `task-orchestration` и тесты; `restart` как штатный выход |
| Справочник по ИТОГИ неточен | Каждый тезис — из источников; в конце список источников; ключевое правило совпадает с автоматическим правилом |
| Изменения template не попадают в уже созданные проекты | Вне scope: для существующих проектов нужен `update-env`; упомянуть в отчёте |
| Удаление требований о комментариях снижает документированность | Заголовки методов и модуля остаются обязательными; обоснования — в `DEVELOP.md` |
