# Ядро окружения + мастер установки — дизайн (подсистема №1)

Дата: 2026-10-01
Статус: утверждён к реализации

## Контекст и рамка проекта

`ai_template` — окружение для ИИ-разработки на 1С (среды Linux и Windows, IDE VS Code,
LLM Claude). Общая цель и полное описание — в `tmp/PLAN.md`.

Зафиксированные рамочные решения (касаются всех подсистем):

- **Своя реализация, deps как референс.** Код пишем свой, подсматривая идеи и куски в
  `deps/` (не форк, не доработка чужих репозиториев).
- **Кросс-платформенность Linux + Windows.**
- **Рантайм:** окружение и платформа 1С — нативно на хосте (VS Code, Claude Code CLI,
  платформа, тестовая база — на хосте). В Docker — **только MCP-серверы** (одинаково на
  Linux и Windows). Запуск 1С/тестов — нативно через пакетные операции (`1c-batch-py`).
- **Единое Web-приложение на базе agentmon** (`deps/ai_env/agent-monitor`): установщик,
  мастер задач и оркестратор — модули одного web-приложения. agentmon уже даёт реестр
  проектов (SQLite), очередь задач с автоподачей, чат с сессией, стоп/резюм, запуск
  агента в PTY (local/ssh), чтение JSONL-журналов, учёт токенов/стоимости/фазы.

### Декомпозиция всего проекта (контекст)

Проект делится на подсистемы, каждая со своим циклом spec → plan → реализация:

1. **Ядро окружения + мастер установки** ← этот спек
2. Содержимое окружения (субагенты, скилы, правила, хуки)
3. Система задач (мастер задач, `tasks/task#id`, этапы, статусы, md-артефакты)
4. Автономный раннер списка задач
5. Бенчмарки

## Цель подсистемы №1

Дать возможность из Web-приложения **создать новый 1С-проект, готовый к ИИ-разработке**
(или обновить существующий): разложить структуру окружения на диске, собрать настройки
через визуальный мастер, подключить MCP-серверы (свои в Docker или уже готовые),
выгрузить конфигурацию/расширения и зарегистрировать проект в agentmon.

## Референсы

- `deps/ai_env/agent-monitor` — базовое web-приложение (расширяем его).
- `deps/docker_1c_sandbox` — как поднимаются MCP-серверы в Docker (образы, compose).
- `deps/1c-batch-py` — пакетные операции с платформой (выгрузка cf/cfe и пр.).
- `deps/code-index-mcp`, `deps/1c-agent-based-dev-framework`, `deps/cc-1c-skills` —
  источники MCP/контента (контент — подсистема №2).

## Решения

### Источник истины конфигурации — Вариант A

- `ai1c.config.json` в каталоге проекта — **источник истины**. Версионируется в git,
  переносится между машинами (Linux↔Windows), читается claude и хуками.
- Реестр agentmon (SQLite) лишь ссылается на путь проекта и кэширует имя/бэкенд; при
  открытии проекта agentmon перечитывает файл.
- **Секреты не коммитим.** Токены (напр. API-ключ Напарника) хранятся в `.env`/секретах
  монитора; в `ai1c.config.json` — только имя переменной окружения, не значение.

### MCP: режим на каждый сервер — managed / external

При создании проекта для каждого из подключаемых MCP пользователь выбирает режим:

- **managed** — сервер поднимается в Docker нами: мастер добавляет сервис в
  `docker-compose.mcp.yml`, пробрасывает порт на `127.0.0.1`, lifecycle (up/down/health)
  делает agentmon на хосте.
- **external** — сервер уже есть у пользователя: он указывает готовый endpoint (url) или
  команду/путь; мастер пишет это в `.mcp.json`, Docker не трогает.

## Layout окружения на диске

После установки каталог проекта:

```
<project>/
├─ .claude/
│  ├─ agents/             # 5 субагентов (контент — подсистема №2)
│  ├─ skills/             # скилы 1С
│  ├─ hooks/              # хуки
│  └─ settings.json       # модели/effort субагентов, разрешения
├─ .mcp.json             # подключение MCP-серверов
├─ ai1c.config.json      # конфиг окружения (источник истины, Вариант A)
├─ docker-compose.mcp.yml# генерируется из выбранных managed-MCP
├─ src/
│  ├─ cf/                 # выгрузка конфигурации
│  └─ cfe/                # выгрузка расширений
├─ tasks/                # задачи (подсистема №3)
└─ CLAUDE.md             # правила проекта
```

Подсистема №1 создаёт структуру и размещает контент; наполнение `.claude/*` —
подсистема №2 (здесь только раскладка/обновление файлов).

## Содержимое `ai1c.config.json`

Всё, что собирает мастер:

- имя проекта, каталог проекта;
- идентификатор разработчика, email;
- каталог платформы, версия платформы;
- база: тип (`server` | `file`) + строка подключения; адрес веб-публикации;
- выбранные MCP: по каждому `{ id, enabled, mode: managed|external, endpoint|command, secret_env? }`;
- модели агентов: по каждому субагенту `{ agent, model, effort }`;
- версия схемы конфига (для миграций при обновлении).

## Мастер установки (Web) — экран «Создать проект»

Новый экран в agentmon. Одна форма с секциями и валидацией:

1. **Режим** — новое окружение / обновить существующее (указать каталог → читается текущий
   `ai1c.config.json`, поля предзаполняются).
2. **Проект** — имя, каталог.
3. **Разработчик** — идентификатор, email.
4. **Платформа** — каталог платформы, версия (скан стандартных путей, предложение найденных
   версий).
5. **База** — тип (серверная/файловая) + строка подключения; адрес веб-публикации.
6. **MCP** — по каждому из 5: чекбокс «подключить» + режим managed/external; для external —
   url/команда/путь; для managed — при необходимости имя переменной секрета.
7. **Модели агентов** — таблица «субагент → модель + effort» (5 строк) с дефолтами.
8. **Действия по завершении** — галки: выгрузить cf в `src/cf`; выгрузить cfe в `src/cfe`;
   поднять managed-MCP сейчас.

По **Submit** бэкенд последовательно:

1. создаёт layout каталогов;
2. пишет `ai1c.config.json`;
3. раскладывает `.claude/*` и `CLAUDE.md` (контент из №2);
4. генерирует `.mcp.json` и `docker-compose.mcp.yml`;
5. (опц.) `docker compose up -d` для managed-MCP;
6. (опц.) выгрузка cf/cfe через `1c-batch-py`;
7. регистрирует проект в реестре agentmon.

Прогресс шагов стримится в UI (SSE/лог) — выгрузка cf долгая. Ошибки (платформа, docker)
ловятся и показываются пользователю, шаг можно повторить.

## MCP: каталог, подключение

- Встроенный **каталог MCP** описывает 5 серверов: `id`, как поднимать в Docker
  (образ / фрагмент compose), как подключается claude, нужны ли секреты. Пять серверов:
  `1c-md`, `1c-syntax-checker-mcp`, `bsl-platform-context`, `1c-naparnic`, `code-index`.
- **managed:** сервис в `docker-compose.mcp.yml`, порт на `127.0.0.1:PORT`; в `.mcp.json`
  claude подключается предпочтительно по **HTTP/SSE** (`url: http://127.0.0.1:PORT`), а для
  stdio-only серверов — через `docker exec -i <container>`.
- **external:** в `.mcp.json` пишется указанный пользователем endpoint/команда; Docker не
  трогаем.
- Один `.mcp.json` одинаково работает на Linux/Windows — порты на `127.0.0.1`.

## Выгрузка cf/cfe

Через `deps/1c-batch-py` (нативная платформа на хосте): выгрузка конфигурации в `src/cf` и
расширений в `src/cfe`. Длительная операция → прогресс в UI, ошибки платформы ловятся и
показываются. В режиме обновления — повторная выгрузка поверх.

## Режим обновления

- Читает существующий `ai1c.config.json`, показывает поля предзаполненными.
- **Сохраняет пользовательские правки:** `CLAUDE.md`/`settings.json` не перетираются вслепую
  — мерж или бэкап перед заменой.
- Обновляет контент `.claude/*` из №2.
- Мигрирует схему конфига при необходимости (по версии схемы).
- Перегенерирует `.mcp.json` / `docker-compose.mcp.yml` под новый выбор MCP.

## Границы (что НЕ входит в №1)

- Контент субагентов/скилов/правил/хуков — подсистема №2 (№1 лишь раскладывает/обновляет
  файлы).
- Мастер задач, этапы, статусы, `tasks/task#id` — подсистема №3.
- Автономный прогон списка задач — подсистема №4.
- Бенчмарки — подсистема №5.

## Тестирование

- Юнит-тесты генерации `ai1c.config.json`, `.mcp.json`, `docker-compose.mcp.yml` из
  входных настроек (managed/external, набор MCP) — на временном каталоге.
- Тест idempotent-обновления: повторный запуск с теми же настройками не теряет
  пользовательские правки `CLAUDE.md`/`settings.json`.
- Тест миграции схемы конфига (старая версия → новая).
- Нормализация путей Linux/Windows (следуя подходу agentmon по `cwd`).
- cf/cfe-выгрузка и реальный `docker compose up` — через мок/заглушку в юнит-тестах;
  живой прогон — отдельным ручным/интеграционным сценарием.
