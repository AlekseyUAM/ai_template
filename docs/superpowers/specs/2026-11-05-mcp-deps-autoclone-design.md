# Автоклонирование исходников deps при развёртывании MCP в Docker

Дата: 2026-11-05

## Проблема

Кнопки «Развернуть в Docker локально» (`app/web/mcp.js`) вызывают
`POST /api/mcp/{id}/launch[/stream]`. Для видов `1c-platform` и `code-index`
эндпоинт собирает образ из Dockerfile, лежащего в `deps/`:

- `deps/docker_1c_sandbox/mcp-bsl-context/Dockerfile` — вид `1c-platform`;
- `deps/code-index-mcp/deploy/docker/Dockerfile` — вид `code-index`.

Каталог `deps/` целиком исключён из репозитория (`.gitignore: /deps/*`).
На чистом клоне при первом нажатии кнопки `docker build` падает: Dockerfile и
контекст сборки отсутствуют. Пользователь вынужден вручную клонировать
репозитории, что нигде в UI не подсказано.

## Цель

Перед сборкой образа автоматически клонировать нужный исходный репозиторий в
`deps/`, если его там ещё нет, и показать ход клонирования в том же логе, что и
сборку/запуск. Ручная подготовка `deps/` больше не требуется.

## Решения, принятые при обсуждении

- **Момент клонирования:** только если образ ещё не собран (`need_build`).
  Если образ есть, deps не нужны и сеть не трогаем.
- **URL:** публичные HTTPS-адреса (проверена доступность без SSH-ключей):
  - `https://github.com/AlekseyUAM/docker_1c_sandbox.git`
  - `https://github.com/Regsorm/code-index-mcp.git`
- **Глубина клона:** `--depth 1` (история сборке не нужна).
- **Существующий каталог:** считаем исходники уже скачанными, ничего не трогаем
  (идемпотентность). Обновление deps — отдельная задача, не входит в эту.

## Архитектура

Знание «какой репозиторий нужен виду MCP» хранится рядом с рецептом сборки —
в `BuildSpec`, а не отдельным словарём в API.

### 1. `app/src/agentmon/env/mcp_docker_recipes.py`

В `BuildSpec` добавляются необязательные поля:

| поле | назначение |
| --- | --- |
| `repo_dir` | каталог исходников относительно корня репозитория |
| `repo_url` | HTTPS-URL git-репозитория для клонирования |

Заполняются для двух рецептов:

| вид | `repo_dir` | `repo_url` |
| --- | --- | --- |
| `1c-platform` | `deps/docker_1c_sandbox` | `https://github.com/AlekseyUAM/docker_1c_sandbox.git` |
| `code-index` | `deps/code-index-mcp` | `https://github.com/Regsorm/code-index-mcp.git` |

У `bsl-ls` поля остаются пустыми: образ собирается из `app/docker`, deps не
нужен. У `1c-naparnic` `build is None` — только готовый образ. `repo_dir` и
`repo_url` задаются только вместе; команда клонирования строится только когда
заданы оба.

Сабмодули `docker_1c_sandbox` для сборки `mcp-bsl-context` не требуются: нужный
jar лежит в репозитории обычным файлом (`mcp-bsl-context/source/jar/…jar`), а
Dockerfile его только копирует. Поэтому `--recurse-submodules` не используем.

### 2. Новый модуль `app/src/agentmon/env/mcp_sources.py`

Функции строят и выполняют команду клонирования; `run` инъектируется для
тестов.

- `clone_cmd(build, repo_root)` → `list[str] | None`:
  - `None`, если `build is None`, `repo_url` не задан или каталог
    `repo_root / repo_dir` уже существует;
  - иначе `["git", "clone", "--depth", "1", repo_url, str(dest)]`.
- `clone(build, repo_root, run=subprocess.run)` → `{"ok", "cloned", "log"}`:
  - `cloned=False, ok=True`, если команды нет;
  - иначе выполняет команду, склеивает stdout+stderr, `ok` — код возврата 0.

### 3. Блокирующий запуск — `mcp_api.launch_mcp`

Если `need_build`:

1. вызвать `mcp_sources.clone`;
2. добавить его лог в общий лог;
3. при `ok=False` вернуть `{"ok": False, "log": ...}` с сообщением об ошибке
   клонирования и **не** запускать `docker build`.

### 4. Стриминговый запуск — `mcp_api.launch_mcp_stream`

Перед секцией «Сборка образа», если `clone_cmd` вернул команду:

1. вывести заголовок `=== Скачивание исходников ===` и саму команду;
2. построчно стримить её вывод через `mcp_docker.iter_output`;
3. при ненулевом коде возврата вывести ошибку и завершить генератор, не
   переходя к сборке.

### 5. Не затрагивается

- вид `bsl-ls` — сборка из `app/docker`, deps не используется;
- вид `1c-naparnic` — только готовый образ, сборки нет;
- кнопка «Развернуть локально» (`code-index-local`) — скачивает релиз с GitHub,
  deps не использует;
- скачивание cfe — `deps/mcp_tools_cfe` входит в репозиторий.

## Обработка ошибок

- Нет `git` или нет сети → `git clone` вернёт ненулевой код; запуск
  прерывается, вывод команды виден в логе UI. Исключения наружу не выпускаем.
- Каталог существует, но неполный/битый → считаем скачанным; пользователь
  удаляет каталог вручную. Автоматическая починка — вне рамок задачи.
- Клонирование идёт только при необходимости сборки, поэтому готовый образ
  позволяет работать полностью офлайн.

## Тесты

- `app/tests/env/test_mcp_sources.py`:
  - нет `repo_url` → `clone_cmd` = `None`;
  - каталог уже есть → `None`;
  - каталога нет → корректная команда `git clone --depth 1`;
  - `clone` успех/ошибка (инъекция `run`), лог склеен.
- `app/tests/env/test_mcp_api.py`:
  - блокирующий `/launch` для `code-index` без каталога deps: сначала clone,
    затем build (monkeypatch обеих функций, проверка порядка);
  - ошибка clone → `ok=False`, build не вызван;
  - стриминговый `/launch/stream`: в теле есть `Скачивание исходников` и
    вывод clone до `Сборка образа`;
  - существующие тесты (bsl-ls, готовый образ) не меняют поведение.
- Полный прогон `app/tests/env`.
