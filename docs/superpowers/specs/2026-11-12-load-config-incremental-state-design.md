# Инкрементальная частичная загрузка конфигурации (state по задаче)

Дата: 2026-11-12

## Проблема

`template/.claude/tools/load-config-optimized.py` определяет изменённые файлы как
`git diff HEAD -- src/cf` + untracked. Внутри задачи коммитов нет, поэтому список
только растёт: файлы метаданных, созданные в начале задачи, остаются в diff при
каждой последующей загрузке.

Хуже того, при добавлении объекта меняется `Configuration.xml`, а его наличие в
списке заставляет платформу выполнять **полную** загрузку конфигурации (см. навык
`db-load-git`). Пока задача не закоммичена, `Configuration.xml` остаётся в diff, и
каждая итерация разработки — это полная перезагрузка, а не частичная.

## Цель

Грузить только то, что изменилось с момента последней **успешной** загрузки в ИБ,
не делая коммитов внутри задачи. Файлы, уже загруженные и не менявшиеся после
этого, — в том числе `Configuration.xml` — не должны попадать в `-listFile`.

## Решения, принятые при обсуждении

- **Отметка о загрузке — в каталоге задачи:** `logs/task#<id>/load-state.json`,
  путь передаёт оркестратор через необязательный `--state`. Изоляция между
  задачами: новая задача стартует без state, т.е. с полного diff vs HEAD. State
  не портится, если ИБ пересоздали/откатили между задачами.
- **Дельта — манифест хешей:** state хранит `путь → sha256`; из кандидатов
  загружаются только те, чей хеш отличается от сохранённого. Снимок git-дерева
  через временный индекс отклонён: висячие объекты, сложнее тестировать, больше
  платформенных нюансов. Слепок `size + mtime` отклонён: риск ложного
  «не изменился» — пропуск изменения в ИБ.
- **Без `--state` поведение не меняется** (полный diff) — ручной запуск и старые
  сценарии безопасны.
- **State пишется только при успехе** — код возврата 0 либо отсутствие файлов
  для загрузки; при ошибке загрузки state не меняется. Снимок хешей всегда
  фиксируется до запуска загрузки.
- Коммитов внутри задачи нет.

## Алгоритм запуска со state

1. `R` — сырые изменённые пути: `git diff HEAD` + untracked, как сейчас, после
   отбрасывания префикса `src/cf/` и `ConfigDumpInfo.xml`.
2. `S` — состояние из файла. Нет файла / битый JSON / неизвестная `version` →
   пустое состояние + предупреждение в stderr; загрузка не срывается.
3. Кандидаты `U = R ∪ ключи(S)`.
4. Каждому существующему пути из `U` считается sha256 (читаются байты, без
   декодирования). Отсутствующий путь — «удалён».
5. В загрузку идут пути, у которых хеша в `S` нет или он отличается. Совпавшие
   пропускаются — это и убирает из списка `Configuration.xml` и файлы
   метаданных, не менявшиеся после прошлой успешной загрузки.
6. Дальше — существующий разворот путей: корень объекта, формы/макеты, файлы
   `Ext`, исключение `ConfigDumpInfo.xml`.
7. Снимок для нового state — все существующие кандидаты `U` с их текущими
   хешами. Он вычисляется **до** загрузки и записывается в state только при
   коде возврата 0: если загрузка упала, state не трогаем и следующий запуск
   повторит те же файлы; если файл изменили во время загрузки, в state попадёт
   до-загрузочный хеш, и изменение подхватится в следующий раз.
8. Если грузить нечего — state всё равно актуализируется (забыть удалённые пути,
   обновить совпавшие хеши): это ничего не утверждает о БД сверх уже
   загруженного.
9. Ранее загруженный файл, которого больше нет: убирается из state, в список не
   добавляется (поведение как сейчас — частичная загрузка не удаляет части
   объектов); в лог пишется строка-предупреждение.

Объединение с ключами `S` нужно для случая «изменил → загрузил → откатил к
HEAD»: файл исчезает из diff, но его текущий хеш отличается от загруженного —
БД надо вернуть к HEAD-версии.

## Формат state

```json
{
  "version": 1,
  "hash": "sha256",
  "updated_at": "2026-11-12T12:34:56Z",
  "files": {
    "Catalogs/Номенклатура.xml": "9f86d0…",
    "Configuration.xml": "…"
  }
}
```

- Ключи — пути относительно `src/cf` с прямыми слэшами, как в `-listFile`.
- `ConfigDumpInfo.xml` в state не попадает никогда.
- Запись атомарная: временный файл рядом + `os.replace`; родительские каталоги
  создаются.

## Изменения в скрипте

Рефакторинг под тестируемость без запуска 1С:

- `parse_args()` — argparse, единственный параметр `--state PATH`
  (необязательный).
- `get_dirty_paths() -> List[str]` — вынести из `get_changed_files()`: git diff
  + untracked, нормализация, отбрасывание префикса `src/cf/` и
  `ConfigDumpInfo.xml`. Новых git-команд нет — тестовый мок `subprocess`
  остаётся рабочим.
- `expand_to_load_paths(raw) -> List[str]` — текущая логика разворота (корень
  объекта, формы/макеты, `Ext`) без изменений.
- `load_state(path) -> Dict[str, str]` — толерантное чтение.
- `save_state(path, files)` — атомарная запись.
- `filter_loaded(candidates, state, cf_dir) -> (changed, snapshot, deleted,
  skipped)` — один проход с хешированием: изменённые, полный снимок для state,
  удалённые, пропущенные.
- `collect_changes(state) -> (files, snapshot, deleted, skipped)` — связка
  «dirty → filter → expand». `get_changed_files()` остаётся тонкой обёрткой без
  state — существующие тесты не меняются.
- `main()` — разбор аргументов, сбор, печать, запуск, `save_state` при успехе.

Логи дополняются строкой `⏭️ Пропущено как уже загруженное: N` (и списком при
N > 0) — чтобы при разборе лога было видно, почему список сократился.

## Обработка ошибок и крайние случаи

- State никогда не меняет код возврата скрипта: битый/отсутствующий state —
  просто полный diff.
- Ошибка записи state после успешной загрузки (нет прав и т.п.) — предупреждение
  в stderr, скрипт не падает: ИБ уже обновлена, следующий запуск просто загрузит
  лишнее.
- `--state` указывает на каталог — понятная ошибка аргумента.
- Путь `--state` разрешается в абсолютный до `os.chdir(project_root)` в
  `get_dirty_paths()`, чтобы относительный путь не зависел от текущего каталога
  запуска.
- Удаления, видимые `git diff`, обрабатываются как раньше (корень объекта
  добавляется, если существует). Пути, удалённые только из state (untracked,
  созданные и удалённые внутри задачи), в расширение не передаются.
- Кодировка/бинарность файлов не важны: хешируются байты.
- Пути нормализуются к прямым слэшам на всех платформах.

## Тесты

pytest, `app/tests/env/test_load_config_optimized.py`; прогон
`python -m pytest -q`:

1. Первый запуск со state: файл создан, содержит sha256 всех кандидатов.
2. Повторный запуск без изменений: список пуст — в т.ч. `Configuration.xml` не
   попадает.
3. Правка модуля после загрузки: грузится только он (+ `Ext` объекта),
   метаданные и `Configuration.xml` пропущены.
4. Откат файла к HEAD (из diff исчез, в state есть) — определяется по хешу и
   грузится.
5. Удалённый файл из state — забывается, без падения.
6. Отсутствующий/битый state — полный diff (поведение как сейчас).
7. Неуспешная загрузка — state не перезаписан.
8. Существующие регрессионные тесты (новый отчёт с формами, исключение
   `ConfigDumpInfo`) проходят без изменений.

## Не входит в объём (YAGNI)

- Проектный (межзадачный) state и гибрид «проектный + `--state`».
- Снимок git-дерева через временный индекс и `git stash create`/`commit-tree`.
- Изменения в навыке `db-load-git` — он ручной и в оркестрации задач не
  участвует.
- Автоопределение `task#<id>` внутри скрипта и флаг `--reset`.
