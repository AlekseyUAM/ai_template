# Условное окружение под MCP `1c-md`: `validate_query`

Дата: 2026-11-12

## Проблема

Шаблон окружения (`template/.claude`) сейчас одинаков для любого набора MCP.
Если в проект добавлен MCP вида «Метаданные (http-сервис в 1С)» (`1c-md`) или
«Метаданные + произвольные запросы (http-сервис в 1С)» (`1c-md-queries`),
у агента появляется платформенная проверка запросов `validate_query`, но навык
`mcp-usage` о ней не знает, а навык `query-analyze` проверяет синтаксис только
локальным SDBL-парсером.

`validate_query` вызывает `СхемаЗапроса.УстановитьТекстЗапроса` в самой
платформе: это точнее локального парсера и учитывает актуальные метаданные
информационной базы.

## Цель

При разворачивании проекта, если в списке MCP включён `1c-md` или
`1c-md-queries`:

1. Дополнить `mcp-usage/SKILL.md` описанием MCP `1c-md` и инструмента
   `validate_query`. Обязательно предупредить: если метаданные правились в
   XML-исходниках и ещё не загружены в БД, `validate_query` про них не знает и
   выдаст ошибки на корректном запросе.
2. Дополнить `query-analyze/SKILL.md`: `validate_query` — первый слой проверки
   каждого текста запроса; локальный анализатор остаётся для стилевых и
   оптимизационных правил и как fallback, если `validate_query` недоступен.

Без MCP `1c-md` условные фрагменты в проект не попадают; единственное
безусловное изменение — нейтральная вводная фраза в `mcp-usage` без счётчика
серверов.

## Решения, принятые при обсуждении

- **Триггер — оба вида** (`1c-md`, `1c-md-queries`). Пользователь отдельно
  доработает `deps/mcp_tools_cfe/MCP_Сервер.cfe`, чтобы `validate_query` был и в
  базовом расширении. В тексте навыка `validate_query` описан как «если доступен».
- **`validate_query` — первый слой, не единственный.** Локальные стилевые и
  оптимизационные проверки (`select-star`, фильтры виртуальных таблиц и т.п.)
  остаются.
- **Условный контент хранится в самих `SKILL.md`** под маркерами, без отдельных
  файлов-вариантов и без Python-констант с текстом.

## Архитектура

### Триггер

Источник истины — сохранённый список MCP проекта (`config.mcp`,
`McpSelection`), а не `.mcp.json`: имена серверов в `.mcp.json` произвольны и не
кодируют вид.

```python
has_1c_md = any(
    getattr(sel, "enabled", False) and sel.id in ("1c-md", "1c-md-queries")
    for sel in config.mcp
)
```

- Выключенная карточка (`enabled=False`) не считается.
- Учитываются оба вида.
- Проверка выполняется при создании и при `update-env` (`config.mcp` там
  собирается из связей проекта).

### Маркеры в шаблоне

В текстовых файлах `template/.claude` допускаются блоки:

```markdown
<!-- @if 1c-md -->
…условный фрагмент…
<!-- @endif -->
```

Правила:

- Условие одно — `1c-md` (означает «включён любой из двух видов»). Без
  вложенности, без выражений, без общего шаблонизатора.
- `has_1c_md=true`: строки-маркеры удаляются, содержимое остаётся.
- `has_1c_md=false`: удаляется весь блок вместе с маркерами.
- На стыке блока схлопывается лишняя пустая строка, чтобы Markdown оставался
  чистым в обоих вариантах.
- Незакрытый или вложенный блок — ошибка разворачивания с путём к файлу: лучше
  упасть, чем выпустить маркеры в целевой проект.
- Файлы без маркеров и без подстановок, как и сейчас, не перезаписываются.

### Точка интеграции — `app/src/agentmon/env/content.py`

Обработка встраивается в существующий проход `_apply_mcp_names` (переименуется в
`_render_template_texts`): он уже обходит все текстовые файлы `template/.claude`,
подставляет имена MCP и пишет на цель только изменившееся. Добавляется второй
шаг — рендер условных блоков с `has_1c_md`.

`deploy_content` вычисляет `has_1c_md` из `config.mcp` и передаёт в проход.
Проход вызывается после `put_tree` и при создании, и при обновлении, поэтому при
изменении состава MCP блок появляется или исчезает сам; пользовательские правки
в целевых файлах по-прежнему сохраняются в `.bak` на обновлении.

При записи изменённого файла проход применяет и подстановку интерпретатора
`.venv` (ту же, что `_rewrite_python_invocations`): `query-analyze/SKILL.md`
содержит и вызовы `python …`, и условные блоки, поэтому запись без этой
подстановки вернула бы в целевой файл голый `python`.

Подстановка имён MCP (`mcp_name_overrides`) продолжает работать: в шаблоне
инструмент пишется как `mcp__1c-md__validate_query`, при переименованном сервере
`1c-md` заменится на фактическое имя.

## Правки контента

### `template/.claude/skills/mcp-usage/SKILL.md`

- Вводная фраза «Четыре сервера…» заменяется на нейтральную без счётчика
  («Серверы ниже…»), чтобы не зависеть от условия.
- В таблицу быстрого выбора добавляется строка (внутри условного блока):
  «Проверить синтаксис текста запроса по метаданным ИБ → `1c-md` →
  `validate_query`».
- Новая секция `## 1c-md — метаданные и проверка запросов платформой`:
  - расширение 1С с HTTP-сервисом, работает по актуальным метаданным ИБ, а не по
    XML-исходникам;
  - `validate_query` (`queryText`): проверка синтаксиса платформой через
    `СхемаЗапроса`, без выполнения и без обращения к данным; возвращает
    `valid` и `message`;
  - предупреждение о незагруженных метаданных: имена, добавленные в XML и ещё не
    загруженные в БД, вызовут ошибку «не найдено» на корректном запросе; такие
    имена сверять с XML (`meta-info`, `code_index`), запрос под устаревшую БД не
    переписывать, после загрузки изменений в ИБ повторить проверку;
  - отличие от `query-analyze`: платформа проверяет синтаксис и имена по ИБ, но
    не проверяет стилевые и оптимизационные стандарты.
- В «Рецепты» добавляется пункт: проверить запрос → `validate_query`, затем
  `query-analyze` для стилевых правил.

### `template/.claude/skills/query-analyze/SKILL.md`

После вводного абзаца добавляется условная преамбула:

1. Извлечь запросы прежним способом (`extract_queries.py`).
2. Каждый текст проверить `validate_query` (`{"queryText": "<текст>"}`).
3. `valid: false` — разобрать `message` и исправить. Если причина — метаданные,
   ещё не загруженные в БД, подтвердить имена по XML и не считать это дефектом
   запроса.
4. Затем прогнать локальный `analyze_query.py` — стилевые и оптимизационные
   правила, которых `validate_query` не проверяет.
5. Если `validate_query` недоступен (MCP не подключён или сборка расширения без
   инструмента) — работать по локальному анализатору, как описано ниже.

Вызов `validate_query` выполняют субагенты, у которых `tools` в frontmatter —
жёсткий allow-list. Поэтому во всех шести агентах (`analyst`, `architect`,
`developer`, `developer-tests`, `reviewer`, `technical-writer`) в конец строки
`tools:` добавляется плейсхолдер `{{MCP_1C_MD_TOOLS}}`; при разворачивании он
заменяется на `, mcp__<фактическое имя>__*`, если включён `1c-md`, и на пустую
строку иначе. Без MCP строки `tools` остаются прежними; при переименованном
сервере подставляется его имя. Маркеры `<!-- @if -->` в YAML-frontmatter
неприменимы, поэтому здесь используется плейсхолдер.

## Тесты

- Юнит-тесты рендера маркеров: включённый блок, выключенный блок, удаление
  маркеров, нормализация пустых строк, ошибка на незакрытом блоке.
- Деплой с `McpSelection(id="1c-md", enabled=True)` и с `1c-md-queries` → в
  обоих `SKILL.md` есть `validate_query` и предупреждение о незагруженных
  метаданных; маркеров нет.
- Деплой без `1c-md` или с `enabled=False` → упоминаний `validate_query` нет,
  маркеров нет; остальное содержимое навыков прежнее.
- `update-env` в обе стороны: блок появляется и исчезает по актуальному списку
  MCP.
- Переименованный сервер (`connection` с именем `my_md`) → в целевом тексте
  `mcp__my_md__validate_query`.
- Во всех шести агентах при включённом `1c-md` в `tools` появляется
  `mcp__1c-md__*` (или имя переименованного сервера); без `1c-md` строки `tools`
  не меняются, плейсхолдер не протекает.
- Уточнение в тексте навыков: `meta-info` назван навыком, а не MCP-инструментом.

## Вне рамок

- Полноценный шаблонизатор и другие условия, кроме `1c-md`.
- Автоматическая проверка доступности `validate_query` во время работы агента —
  в тексте навыка остаётся указание «если доступен».
- Генерация и проверка `.mcp.json`.
- Доработка самих расширений 1С (`MCP_Сервер.cfe` делает пользователь).
- Документация `docs/mcp/` и внутренний набор MCP AgentMon.

## Риски

- **Ложные ошибки из-за устаревшей БД.** Снимаются предупреждением в обоих
  навыках: сверять имена с XML-исходниками.
- **MCP включён в карточке, но сервер недоступен.** Навык предписывает fallback
  на локальный анализатор.
- **Маркеры в шаблоне.** Сбалансированность проверяется тестом и ошибкой
  разворачивания; в целевой проект маркеры не попадают.
