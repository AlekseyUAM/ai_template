## Task 1: Модель задач v2 (task_model.py)
**Interfaces:**
- `DEFAULT_STAGES` — 7 этапов (name/subagent/artifact), как в Фазе 0 `task_schema`.
- `build_stages(enabled_names, gated_names=()) -> list[dict]` — каждый этап dict с enabled, gate (in gated), approved=False, status pending/skipped, changed_files=[].
- `overall_status(stages) -> str` — planned→(если есть running→running; все enabled done→done; gated done & not approved & есть pending после → awaiting_user; есть failed→failed; иначе planned). Приоритет: failed > awaiting_user > done > running > planned.
- `validate_task(*, name, goal, plan, constraints, tests, enabled_names) -> list[str]` — ошибки: пустые name/goal/plan/constraints; tests пуст при включённом этапе 'tests'; 'testing' включён без 'tests'.

## Task 2: API задач v2 (task_api2.py)
**Interfaces:** `build_task2_router(store) -> APIRouter`; create_app подключает.
- `POST /api/env/tasks` body `{project_id, name, goal, plan, constraints, tests, enabled_stages[], gated_stages[]}` → validate_task (400 с ошибками); `stages_json=json(build_stages(...))`; `TaskRepo.add(...)`; записать на диск `<project.path>/tasks/task#<id>/TASK.md`+`task.json` (проект берётся из ProjectRepo по project_id для пути); вернуть `{task}`.
- `GET /api/env/tasks?project_id=` / `GET /api/env/tasks/{id}` / `DELETE /api/env/tasks/{id}`.
- `POST /api/env/tasks/{id}/stage` `{stage, status, changed_files?}` → обновить этап в stages_json; пересчитать overall; `TaskRepo.set_status(id, overall, stage)`; если gated-этап стал done и не approved → status=awaiting_user.
- `POST /api/env/tasks/{id}/approve` `{stage}` → approved=true у этапа; пересчитать overall (обычно → planned/queued); сохранить.
- `GET /api/env/tasks/{id}/overall` → `{overall}`.
- 503 если store None.
