> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Внедрить оркестраторный красный смоук после `tests`, продолжение `tests`/`develop` через SendMessage, правило движений для регистра остатков и возврат из `review` по принадлежности находки.

**Tech Stack:** Markdown-промпты Claude Code, `pytest`, git (локальный `main`).

**Спека:** `docs/superpowers/specs/2026-11-13-agent-pipeline-smoke-sendmessage-design.md`.

Перед заголовком `## Загрузка в базу после этапа \`develop\` (флаг \`update_db\`)`
вставить целиком:

````markdown
## Красный смоук после этапа `tests` (ведёт оркестратор)
Смоук — часть завершения этапа `tests`, до `develop`. Он ловит ошибки компиляции
тест-модуля, ошибки setup и зелёные тесты до реализации. Субагент тесты не запускает:
загрузку расширения и прогон ведёт оркестратор.

1. После того как автор тестов записал `TESTS.md` и
   `configs/task#<id>/test.json`, **не закрывай этап `tests`** — он остаётся `running`.
2. Загрузи расширение и запусти набор в фоне (см. «Долгие фоновые операции»):
   ```bash
   python .claude/skills/1c-batch/scripts/1c-batch.py load-extension src/cfe/ЮнитТесты --name ЮнитТесты > logs/task#<id>/load-extension-tests.log 2>&1
   python .claude/tools/run-tests.py configs/task#<id>/test.json --timeout 120 > logs/task#<id>/run-tests-smoke.log 2>&1
   ```
   Полный набор, а не один сценарий: прогон занимает около минуты. `--test` — только
   для отладки.
3. Проснувшись, прочитай `logs/task#<id>/run-tests-smoke.log` и `result.json`
   (`ИмяФайлаЛог` из конфига). Смоук пройден, только если:
   - код возврата `0` (`1`/`3` — ошибка среды: зафиксируй и остановись, цикл не гоняй;
     `124` — зависание теста);
   - `Выполнено = true`, `ОписаниеОшибки = null`;
   - ни у одного теста нет `Результат = true` — до реализации все тесты обязаны быть
     красными;
   - красные падают по утверждению (expected/actual) или по ожидаемому отсутствию ещё
     не написанной функциональности, а не по ошибке компиляции/setup тест-модуля.
   Если причина красного неочевидна, не угадывай: отправь лог автору тестов через
   SendMessage и попроси подтвердить причину.
4. Дефект теста — SendMessage автору (см. «Продолжение субагента (SendMessage)»);
   автор чинит тест-модуль, не ослабляя проверку; повтори смоук. Максимум 2–3 цикла
   «смоук → правка → смоук». После лимита пометь `tests` как `failed` и остановись.
5. Смоук пройден — `task_status.py ... tests done --files <изменённые>`, дальше
   `develop`.

Особые случаи:
- ошибка компиляции в `ЮнитТесты` — дефект теста, SendMessage автору;
- ошибка компиляции в `src/cf` — дефект baseline, тест-модуль не виноват: зафиксируй
  лог, закрой `tests` и передай лог разработчику на `develop`; после `develop` смоук
  повторится в рамках `testing`;
- зелёный тест до реализации — дефект теста: он проверяет не новое поведение.

````

- [ ] **Шаг 4: Вставить раздел о SendMessage**

Перед заголовком `## Статусы` вставить целиком:

````markdown
## Продолжение субагента (SendMessage)
Если субагент этапа уже запускался, возврат на **тот же этап** (`tests` из
смоука/`testing`, `develop` из `testing`/`review`) выполняй продолжением агента через
SendMessage, а не новым запуском. Это сохраняет контекст правок и не заставляет агента
заново читать большие артефакты.

1. После запуска субагента сохрани его идентификатор в
   `logs/task#<id>/agents.json` (если инструмент его вернул):
   ```json
   {
     "tests": {"agent_id": "<id>", "iteration": 1},
     "develop": {"agent_id": "<id>", "iteration": 1}
   }
   ```
   Если идентификатор не вернулся — запиши `null`.
2. Перед возвратом прочитай `agents.json` и продолжи агента через SendMessage с коротким
   re-brief:
   > Ты продолжаешь этап `<этап>` (итерация `<n>`). Перед правкой прочитай текущие
   > `<артефакт>` (путь), `TESTING.md`/`REVIEW.md` (путь) и лог (путь). Вердикт:
   > `<вердикт>`. Твоя зона: `<зона>`. Не меняй `<ограничения>`. Верни краткий отчёт:
   > что прочитал, что изменил, какие проверки выполнил.
3. После ответа проверь, что артефакт изменился и отчёт соответствует задаче. Если нет —
   fallback на нового агента.
4. Новый агент запускай, если: идентификатора нет; SendMessage недоступен; агент не
   резюмировался; две попытки подряд на одном дефекте не дали результата. После двух
   неудач продолжение прекращай — это защита от «защиты своего артефакта».
5. SendMessage — только для того же этапа и того же артефакта. Смену роли (`tests` →
   `develop`) он не выполняет. Статусы, артефакты, архивирование и вердикты остаются за
   оркестратором.
6. При переименовании артефакта (`TESTS.md` → `TESTS.<n>.md`) в re-brief передавай
   точные текущие пути.

````
