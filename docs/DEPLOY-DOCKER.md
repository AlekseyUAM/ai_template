# Деплой монитора в Docker

По умолчанию монитор (control plane AgentMon) запускается **на хосте** (`AI1C_MONITOR_MODE=host`).
Docker-режим — опциональный: монитор упаковывается в контейнер, но логика ядра не меняется.

## Как включить

В файле `.ai1c.env` задайте:

```
AI1C_MONITOR_MODE=docker
```

Затем запустите:

```bash
python run.py
```

`run.py` поднимет `docker compose -f app/docker-compose.yml up --build`.
UI будет доступен по адресу `http://127.0.0.1:${AGENTMON_PORT:-8765}`.

Чтобы вернуться на хост-режим — удалите строку или задайте `AI1C_MONITOR_MODE=host`.

## Что монтируется и почему

| Монтирование | Зачем |
|---|---|
| `../:/opt/ai1c` (корень репо) | Монитор резолвит `template/`, `web/` и прочие пути внутри репо |
| `/var/run/docker.sock` | Монитор запускает MCP- и docker-бэкенд-контейнеры |
| том `agentmon_claude` → `/root/.claude` | Авторизация агента (`claude`) переживает рестарт контейнера |
| том `agentmon_data` → `/data` | Данные SQLite, если `AGENTMON_DSN` указывает на SQLite |

`working_dir` внутри контейнера — `/opt/ai1c/app`, `PYTHONPATH=/opt/ai1c/app/src`.

## База данных

Postgres (`ai1c-postgres`) запускается на хосте через `bootstrap.py` и подключается к
общей docker-сети **`ai1c-net`**. Контейнер монитора тоже входит в `ai1c-net` (в
`app/docker-compose.yml` она объявлена `external`), поэтому достаёт БД **по имени
контейнера `ai1c-postgres:5432`** (внутренний порт контейнера), а не через
опубликованный на хосте loopback-порт. `run.py` в docker-режиме:

- автоматически переписывает loopback-DSN (`@127.0.0.1:<port>` / `@localhost:<port>`)
  на `@ai1c-postgres:5432` для контейнера (вручную менять DSN не нужно);
- идемпотентно создаёт сеть `ai1c-net` перед `docker compose up` (если `bootstrap.py`
  ещё не поднимал Postgres).

Порядок: сначала `python bootstrap.py` (поднимает `ai1c-postgres` + создаёт сеть),
затем `AI1C_MONITOR_MODE=docker` → `python run.py`. `host.docker.internal`
(`extra_hosts`) остаётся для прочих ресурсов хоста (не для БД).

> Почему не `host.docker.internal` для БД: `ai1c-postgres` публикует порт только на
> `127.0.0.1` хоста, а `host.docker.internal` из контейнера идёт на gateway-IP — такой
> loopback-publish оттуда недостижим. Общая сеть решает это надёжно.

> Обновление со старого стека: если `ai1c-postgres` был создан до появления сети
> `ai1c-net`, он к ней не подключён — пересоздайте контейнер, чтобы подхватить
> `networks:` из compose: `docker compose -f deploy/postgres/docker-compose.yml up -d`
> (том `ai1c_pg` с данными сохраняется).

SQLite в docker-режиме не рекомендуется (bootstrap при доступном Docker выбирает
Postgres); при необходимости путь к файлу должен быть внутри тома `agentmon_data`
(`/data/...`).

## Авторизация claude

Авторизация сохраняется в именованном томе — вводить токен после каждого рестарта не нужно.
Чтобы авторизоваться (один раз):

```bash
docker compose -f app/docker-compose.yml exec -it agentmon claude
```

Флаг `-it` обязателен — интерактивный вход (`/login`) требует терминала (TTY).
Введите токен по инструкции CLI. Состояние переживает пересборку образа.

## Требования

- Установленный **Docker** + **Docker Compose v2** (`docker compose`, не `docker-compose`).
- Доступный `ai1c-postgres` на хосте (или SQLite-DSN в `AGENTMON_DSN`).

## Execution-модель и бэкенды

`local`-проекты (бэкенд «Локально» в мастере) исполняются **внутри контейнера монитора**.
Для реальной 1С-разработки используйте `ssh`- или `docker`-бэкенды: они исполняют агента
на отдельном хосте или в отдельном контейнере, независимо от контейнера монитора.

## Удалённый Docker-демон (docker-over-ssh)

Docker-бэкенд может работать с **удалённым** Docker-демоном через SSH.

**Как указать удалённый демон при создании проекта:**
В мастере создания проекта (раздел «Размещение», бэкенд «В Docker-контейнере»)
заполните поля **Docker-хост**, **Пользователь** и **SSH-порт**.
Пустые значения означают локальный Docker-демон (поведение не изменяется).

**Требования:**
- Docker CLI с ssh-helper (`docker -H ssh://…`) установлен на машине, где запущен монитор.
- SSH-авторизация настроена через `ssh-agent` или `~/.ssh/config` (без пароля в интерактиве).
- Тулкит-образ (`ai1c-agent:latest` или указанный образ) **собран на удалённом хосте**.
- Внешние ресурсы (сервер 1С, лицензионный сервер NETHASP, MCP-серверы) доступны из сети
  удалённого хоста.

## Опциональный Telegram

`httpx` намеренно не включён в дефолтный образ.
Чтобы активировать Telegram-бота в docker-режиме, добавьте строку в `app/requirements.txt`:

```
httpx
```

Затем пересоберите образ:

```bash
docker compose -f app/docker-compose.yml up --build
```
