# MCP-серверы: развёртывание и подключение

Инструкции по всем видам MCP из справочника AgentMon
(`app/src/agentmon/env/mcp_types.py`): как поднять сервер — кнопкой в UI или
вручную, в том числе на отдельной машине, — и что записать в карточку, чтобы
подключение попало в `.mcp.json` проекта.

## Виды MCP

| Вид в справочнике | Ключ | Где живёт сервер | Порт по умолчанию | Инструкция |
|---|---|---|---|---|
| Произвольный | `custom` | любой внешний MCP | — | [custom.md](custom.md) |
| Метаданные (http-сервис в 1С) | `1c-md` | расширение 1С + веб-публикация | — | [1c-md.md](1c-md.md) |
| Метаданные + произвольные запросы | `1c-md-queries` | расширение 1С + веб-публикация | — | [1c-md-queries.md](1c-md-queries.md) |
| Статический анализ BSL | `bsl-ls` | Docker-контейнер | 8001 | [bsl-ls.md](bsl-ls.md) |
| Справка по платформе | `1c-platform` | Docker-контейнер | 8002 | [1c-platform.md](1c-platform.md) |
| 1С:Напарник | `1c-naparnic` | Docker-контейнер | 8003 | [1c-naparnic.md](1c-naparnic.md) |
| Индексированная кодовая база (в Docker локально) | `code-index` | Docker-контейнер | 8004 | [code-index.md](code-index.md) |
| Индексированная кодовая база (локально) | `code-index-local` | нативный бинарь на хосте | 8005 | [code-index-local.md](code-index-local.md) |

Общее ядро code-index (два процесса, `daemon.toml`, alias проекта) описано
отдельно: [code-index-common.md](code-index-common.md).

## Как подключение попадает в проект

1. «Справочник MCP» → «Добавить» → вид → заполнить поля. Поле «Подключение»
   строится автоматически из полей вида; при необходимости его можно
   отредактировать вручную — это готовый фрагмент `.mcp.json` вида
   `"<имя>": { ... }`.
2. Кнопка вида разворачивает сервер: «Развернуть в Docker локально» — контейнер
   на этой машине; «Развернуть локально» — нативный code-index на хосте.
   Если сервер уже поднят вручную (в том числе на другой машине), кнопка не
   нужна: достаточно указать в карточке правильные `URL`/`Порт` или вписать
   адрес прямо в «Подключение».
3. В мастере проекта выбрать карточку MCP. При создании проекта её фрагмент
   попадает в `.mcp.json` в корне проекта. Ключ сервера в `.mcp.json` — имя из
   фрагмента (`bsl_ls`, `code_index`, `1c_platform`, `1c_naparnic`, `1c-md`).
4. **`.mcp.json` создаётся один раз при создании проекта.** Обновление
   окружения (`update-env`) его не перезаписывает: после изменения карточки
   поправьте `.mcp.json` вручную.

## Общие принципы

- **Контейнеры из UI слушают только `127.0.0.1`** (`-p 127.0.0.1:<порт>:<порт>`,
  `--restart unless-stopped`). Чтобы подключаться с другой машины, разверните
  сервер там и укажите его адрес в поле `URL`/«Подключение».
- **У большинства серверов нет аутентификации** (исключение — токен
  Напарника). Не публикуйте `bsl-ls`, `code-index` и `1c-platform` в интернет
  напрямую: только через reverse-proxy с аутентификацией или в доверенной сети.
- **Порт** карточки должен совпадать с портом, на котором реально слушает
  сервер: он подставляется в строку подключения (`http://<url>:<port>/mcp`).
- **Проверка живости** — HTTP-запрос к эндпоинту (`/mcp` или `/sse`) или вызов
  инструмента из агента.
