# code-index: общее ядро (два процесса, `daemon.toml`, alias)

Оба вида — «в Docker локально» и «локально» — используют один и тот же
бинарь `bsl-indexer` (проект [Regsorm/code-index-mcp](https://github.com/Regsorm/code-index-mcp))
и одну модель запуска. Различаются только способом развёртывания.

## Два процесса

1. **Демон-индексатор** (`bsl-indexer daemon run`) — единственный писатель.
   Читает список путей из `daemon.toml`, строит и поддерживает индекс
   `<каталог кодовой базы>/.code-index/index.db` (пишет его **рядом с кодом**,
   поэтому каталог кодовой базы должен быть доступен на запись).
2. **MCP-сервер** (`bsl-indexer serve ...`) — read-only HTTP-клиент: отдаёт
   `/mcp`, читает тот же `index.db`. Сколько угодно клиентов могут подключаться
   к одному `serve`.

Оба процесса находят друг друга через `CODE_INDEX_HOME` — каталог с `daemon.toml`
и рантайм-файлом `daemon.json`. Если у них разные `CODE_INDEX_HOME`, сервер
отвечает `daemon_offline`, хотя демон жив.

## `daemon.toml`

```toml
[daemon]
http_host = "127.0.0.1"
http_port = 0          # 0 — автовыбор свободного порта (control-сервер демона)
log_level = "info"

[[paths]]
path = "/repos/src"    # в Docker — точка монтирования; локально — реальный путь
alias = "<имя проекта>"
language = "bsl"
```

- в Docker-варианте `path` — всегда `/repos/src` (каталог кодовой базы
  монтируется туда);
- в локальном варианте — реальный абсолютный путь на хосте;
- `alias` в обоих случаях — **имя проекта**.

## Алиас репозитория = имя проекта

Инструменты `code_index` принимают параметр `repo` — алиас репозитория. В этом
окружении **алиас всегда равен имени проекта**.

Три точки, которые обязаны совпадать побайтово:

1. **Имя проекта** (оно неизменяемо после создания; валидируется как
   Python-идентификатор — буквы/цифры/`_`, кириллица допускается).
2. **`daemon.toml`** — `alias = "<имя проекта>"`. При развёртывании из UI файл
   генерируется автоматически; при ручном развёртывании впишите имя проекта
   как есть.
3. **Скилл `mcp-usage`** (`template/.claude/skills/mcp-usage/SKILL.md`) — в
   подсказках агентам стоит плейсхолдер `{{CODE_INDEX_REPO}}`; при развёртывании
   окружения он заменяется на имя проекта (`agentmon.env.content.deploy_content`).

Чего **нельзя** делать:

- применять slug/транслитерацию/приведение регистра к одной из сторон — сервер
  сравнивает алиас точным строковым равенством;
- переименовывать проект в обход UI — алиас в `daemon.toml` и подсказках
  разъедется (пересоздайте `daemon.toml` и обновите окружение).

Агент должен передавать `repo="<имя проекта>"` в инструментах, где параметр
требуется (подробнее — скилл `mcp-usage`). Если в ответе `get_stats` или в тексте
ошибки виден **список** алиасов — репозиториев несколько: берите нужный из
списка. При одном репозитории вызов без `repo` технически проходит, но лучше
передавать явно.

## Проверка и диагностика

```bash
# демон жив и что индексирует
bsl-indexer daemon status --json
# или из агента: health / get_stats
curl -s -H 'Accept: text/event-stream' "http://127.0.0.1:<порт>/mcp"

# перечитать daemon.toml после правки
bsl-indexer daemon reload
```

Пока идёт первичная индексация, инструменты возвращают `{status, progress}`, а
не ошибку. `daemon_offline` означает, что `serve` не нашёл `daemon.json`:
проверьте, что демон запущен и оба процесса используют один `CODE_INDEX_HOME`.
