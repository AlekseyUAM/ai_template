# code_index: параметр `repo` (алиас репозитория)

Почти каждый инструмент MCP-сервера `code_index` (bsl-indexer) принимает параметр
`repo` — **алиас репозитория**, по которому выбирается, в каком индексе искать.
Этот документ фиксирует, какой алиас использовать в нашем окружении и почему.

## Короткое правило

**Алиас репозитория = имя проекта.** Передавай `repo: "<имя проекта>"`.

На один проект разворачивается один MCP-сервер `code_index` с единственным
репозиторием, и его алиас — имя проекта. В подсказках агенту (скилл `mcp-usage`)
на месте алиаса стоит плейсхолдер `{{CODE_INDEX_REPO}}`, который при развёртывании
окружения подставляется на имя проекта.

## Откуда берётся алиас

Источник истины — **имя проекта**. Оно попадает в две точки, которые обязаны
совпадать побайтово:

1. **`daemon.toml`** (сервер). Имя проекта задаётся при создании MCP вида
   «Индексированная кодовая база» в справочнике MCP — поле «Имя проекта
   (alias репозитория)» рядом с «Каталог кодовой базы». Генератор `daemon.toml`
   (`app/src/agentmon/env/mcp_docker_recipes.py`, функция `_daemon_toml`) пишет
   единственную секцию:

   ```toml
   [[paths]]
   path = "/repos/src"
   alias = "<имя проекта>"
   language = "bsl"
   ```

   «Каталог кодовой базы» проекта монтируется в контейнер в точку `/repos/src`
   (том `{catalog_dir}:/repos/src`), а индекс демон держит рядом с кодом
   (`<repo>/.code-index/index.db`). Путь внутри контейнера фиксирован; меняется
   только `alias`.

2. **Скилл `mcp-usage`** (подсказки агенту). Плейсхолдер `{{CODE_INDEX_REPO}}`
   подставляется на `config.project_name` при развёртывании окружения
   (`app/src/agentmon/env/content.py`, `deploy_content`) — и при создании, и при
   обновлении (имя проекта берётся из записи проекта и стабильно).

Имя проекта валидируется как Python-идентификатор (без пробелов/дефисов, Unicode-
буквы допускаются), а алиас у bsl-indexer сравнивается точным строковым равенством
(`BTreeMap::get`), без нормализации/приведения регистра и без ограничения на ASCII.
Поэтому кириллические имена работают — важно лишь, чтобы обе точки получали одну и
ту же строку (имя проекта как есть, **без** slug/нормализации на одной из сторон).

## Можно ли не передавать `repo`

Технически при **единственном** репозитории сервер подставляет его алиас сам, и
вызов без `repo` проходит. Мы всё равно договариваемся **передавать `repo` явно** —
так вызовы самодокументированы и не сломаются, если в окружении появится второй
репозиторий (см. ниже).

## Несколько репозиториев (режим федерации)

Сам bsl-indexer умеет обслуживать несколько репозиториев одним сервером: в
`daemon.toml` перечисляется несколько секций `[[paths]]`, у каждой свой `alias`,
и tool-call выбирает нужный через `repo: "<alias>"`.

Наша обвязка сейчас пишет ровно один `[[paths]]`. Но поведение сервера при вызове
**без** `repo` важно помнить:

| Ситуация | Вызов без `repo` |
| --- | --- |
| Один репозиторий | берётся он (ошибки нет) |
| Несколько, задан `default_repo` в `[mcp]` | берётся `default_repo` |
| Несколько, `default_repo` не задан | **отказ** со списком доступных алиасов |

Поэтому при переходе на мультирепо нужно либо всегда передавать конкретный `repo`,
либо задать `default_repo` в секции `[mcp]` файла `daemon.toml`.

## Практический вывод для агентов

- Обычно: `repo: "<имя проекта>"` (в скилле — `{{CODE_INDEX_REPO}}`).
- Если в ответе `get_stats`/`tools/list` или в тексте ошибки увидишь **список**
  алиасов — значит репозиториев несколько; передавай нужный алиас из этого списка.
