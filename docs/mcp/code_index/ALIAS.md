# code_index: параметр `repo` (алиас репозитория)

Почти каждый инструмент MCP-сервера `code_index` (bsl-indexer) принимает параметр
`repo` — **алиас репозитория**, по которому выбирается, в каком индексе искать.
Этот документ фиксирует, какой алиас использовать в нашем окружении и почему.

## Короткое правило

**В стандартном окружении передавай `repo: "src"`.**

На один проект разворачивается один MCP-сервер `code_index` с единственным
репозиторием, и его алиас — `src`.

## Откуда берётся `src`

Алиас задаётся жёстко при развёртывании сервера. Генератор `daemon.toml`
(`app/src/agentmon/env/mcp_docker_recipes.py`, константа `_DAEMON_TOML`) пишет
единственную секцию:

```toml
[[paths]]
path = "/repos/src"
alias = "src"
language = "bsl"
```

«Каталог кодовой базы» проекта монтируется в контейнер ровно в точку `/repos/src`
(том `{catalog_dir}:/repos/src`), а индекс демон держит рядом с кодом
(`<repo>/.code-index/index.db`). То есть `src` — не вычисляемое из имени проекта
значение, а константа: **один проект = один репозиторий = алиас `src`**.

## Можно ли не передавать `repo`

Технически да: при **единственном** репозитории сервер подставляет его алиас сам,
и вызов без `repo` проходит. Мы всё равно договариваемся **передавать `repo: "src"`
явно** — так вызовы самодокументированы и не сломаются, если в окружении появится
второй репозиторий (см. ниже).

## Несколько репозиториев (режим федерации)

Сам bsl-indexer умеет обслуживать несколько репозиториев одним сервером: в
`daemon.toml` перечисляется несколько секций `[[paths]]`, у каждой свой `alias`,
и tool-call выбирает нужный через `repo: "<alias>"`.

Наша обвязка этот режим **сейчас не использует** — рецепт всегда пишет ровно один
`[[paths]]`. Но если его включить, важно помнить поведение сервера при вызове
**без** `repo`:

| Ситуация | Вызов без `repo` |
| --- | --- |
| Один репозиторий | берётся он (ошибки нет) |
| Несколько, задан `default_repo` в `[mcp]` | берётся `default_repo` |
| Несколько, `default_repo` не задан | **отказ** со списком доступных алиасов |

Поэтому при переходе на мультирепо нужно либо всегда передавать конкретный `repo`,
либо задать `default_repo` в секции `[mcp]` файла `daemon.toml`.

## Практический вывод для агентов

- Сейчас: всегда `repo: "src"`.
- Если в ответе `tools/list` или в тексте ошибки увидишь **список** алиасов —
  значит репозиториев несколько; передавай нужный алиас из этого списка.
