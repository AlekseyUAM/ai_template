# Фазы развития проекта

Проект (окружение ИИ-разработки на 1С) развивается фазами. Ниже — границы каждой.

## Фаза 0 — Прототип (ЗАВЕРШЕНА)

Базовый сквозной прототип на SQLite + файлах, на базе вендоренного `agentmon` (`app/`):

- **Ядро + установщик** (№1): структура окружения на диске, мастер «Создать проект»
  (одностраничный), генерация `.mcp.json`/`docker-compose.mcp.yml`, выгрузка cf/cfe,
  регистрация проекта. Источник истины — `ai1c.config.json`.
- **Содержимое окружения** (№2): субагенты (analyst/architect/developer/tester/
  reviewer/orchestrator), скилы-руководства, правила, Python-хуки, инструменты;
  вендоринг cc-1c-skills (без дублей) + `1c-batch`; деплой через `content.py`.
- **Система задач** (№3): `tasks/task#<id>/` (`task.json` + `TASK.md` + артефакты
  этапов), статус-CLI, API и мастер «Создать задачу», контент оркестрации.
- **Автономный раннер** (№4): отбор задач, сводный статус, постановка в очередь,
  страница «Выполнить задачи».
- **Доработки**: деградируемый Вход субагентов, хук-роутер к оркестратору, ветка git
  на старте задачи; шаблон окружения в корневом `template/`; тёмная тема GitHub;
  удаление чата (две страницы: Проекты, Агенты).
- **Detached-мониторинг**: агенты — отдельные процессы (`claude -p`), слежение по
  PID + код выхода + JSONL + `task.json`; устойчивость к перезапуску монитора.

Состояние: всё на `master`, локально; полный набор тестов зелёный. Это прототип:
хранение — SQLite + файлы, UI — две простые страницы.

## Фаза 1 — Продуктовый UI и модель данных (ЗАВЕРШЕНА*)

Превращение прототипа в удобный продукт. Источник требований — `tmp/NOTE.md`,
`tmp/NOTE1.md` (справочник MCP).

\* Реализованы все буллеты ниже (PostgreSQL-адаптер, стартовая страница и панели,
справочник Проекты с многостраничным мастером и валидациями, справочник MCP под
7 видов, задачи с полем тестов и гейтами, тестовые заглушки, возможности MCP/скилов
в `template/agents`).

Кнопка «Развернуть в Docker локально» работает: `mcp_docker_recipes` задаёт рецепт
на каждый docker-вид (образ, маппинг порта host→внутренний, env, тома), endpoint
`POST /api/mcp/{id}/launch/stream` собирает образ при отсутствии и запускает
контейнер, **стримя лог сборки и запуска построчно** (FastAPI `StreamingResponse`;
UI читает поток и дописывает в панель лога в реальном времени). Блокирующий
`POST /api/mcp/{id}/launch` сохранён (лог целиком).

Проверено вживую: `code-index` (поднят на реальном каталоге, MCP отвечает на `/mcp`)
и `bsl-ls` (образ собран из `app/docker/mcp/bsl-ls.Dockerfile`, BSL LS 1.1.0-rc.6,
mcp-режим отдаёт `/mcp`). Сборка образов идёт с `--network=host` (в sandbox DNS
сборочного namespace недоступен). Поля-предпосылки: `1c-platform` — обязательный
«Путь к платформе» (`ONEC_PLATFORM_PATH` + ro-монтирование); `1c-naparnic` — токен
code.1c.ai + интернет, запуск из готового образа (Dockerfile только в апстриме), на
Linux поднимается в сети хоста (`--network=host`) для внешнего DNS (bridge в sandbox
не резолвит `code.1c.ai`).

- **Хранилище → PostgreSQL**: проекты, задачи, MCP-серверы — во внутренней БД.
- **Стартовая страница** «Agent Monitor v.{версия}»: верхнее меню — справочники
  (Проекты, Задачи, MCP); две панели — «Проекты и задачи» и «Выполнение». Ничего
  лишнего.
- **Панель «Проекты и задачи»**: дерево проект → задачи (удаление, название, путь,
  время выполнения, статус, этап). Статусы задачи: запланирована, в очереди,
  выполняется, остановлена, ожидает пользователя.
- **Панель «Выполнение»**: стеки выполнения — перетаскивание запланированных задач,
  запуск/стоп/удаление стека (удаление срубает процесс), последовательное выполнение
  внутри стека, параллельные стеки, переупорядочивание в незапущенном стеке.
- **Справочник Проекты**: карточка (имя/каталог неизменяемы, кнопка «обновить версию
  окружения» → мастер с предзаполненными полями, хранится версия окружения).
  Мастер создания — **одностраничный** (разделы Проект, Разработчик, Платформа, База,
  MCP, Модели агентов, Действия на одной странице, без шагов Далее/Назад — решение
  зафиксировано, отменяет прежний «многостраничный» вариант из `tmp/NOTE.md`),
  валидация имени (python-идентификатор), пустой каталог, проверка доступа к базе,
  проверка требований (python и т.п.), лог разворачивания.
- **Справочник MCP**: карточка с видами MCP, полями и значениями по умолчанию —
  см. подраздел «Справочник MCP» ниже.
- **Задачи**: владелец (ссылка на проект), поле «тесты» (обязательно при галке tests;
  testing недоступен без tests), кнопки «все/снять галочки», **гейты** (остановка и
  ожидание OK пользователя после выбранных этапов).
- **Тестовые задачи**: заглушки (sleep ~1 мин → успех) для проверки стеков/монитора.
- **Субагенты `template/agents`**: прописать возможности стандартных MCP (считаем все
  поднятыми) и возможности скилов `template/skills`.

### Справочник MCP

Источник требований — `tmp/NOTE1.md`.

**Поведение карточки (общее для всех видов):**

- Поля карточки растянуты на всю ширину — как в карточках задач и проектов.
- Поле «Назначение» — многострочное, как поле «План» в создании задачи.
- Поле «Наименование» — обязательное.
- Поле «Подключение» формируется автоматически при изменении полей «Имя в .mcp.json»,
  «URL» и «Порт» (состав зависит от вида).
- **Баг:** при переходе на страницу MCP первое нажатие «Добавить» не открывает
  создание — срабатывает только со второго нажатия. Исправить.

**Виды MCP и поля карточки:**

- **Произвольный** — поля: Наименование, Назначение, Подключение. Подключение по
  умолчанию:
  ```json
  "name": { "type": "http", "url": "http://localhost:8000/mcp" }
  ```
- **Метаданные (http-сервис в 1С)** — поля: Наименование, Имя в .mcp.json, Назначение,
  URL, Подключение. Имя в .mcp.json по умолчанию `1c-md`; URL по умолчанию `localhost`;
  Назначение по умолчанию «Вся информация об актуальных метаданных конфигурации».
  Подключение:
  ```json
  "1c-md": { "type": "http", "url": "http://localhost/my_database/hs/mcp" }
  ```
  Кнопка «Скачать cfe» → `deps/mcp_tools_cfe/MCP_Сервер.cfe`.
- **Метаданные + произвольные запросы (http-сервис в 1С)** — поля: Наименование, Имя
  в .mcp.json, Назначение, URL, Подключение. Имя в .mcp.json по умолчанию `1c-md`; URL по
  умолчанию `localhost`; Назначение по умолчанию «Произвольные запросы к данным, вся
  информация об актуальных метаданных конфигурации». Подключение — как у
  «Метаданные». Кнопка «Скачать cfe» →
  `deps/mcp_tools_cfe/1c-mcp-tools-1.0.6.cfe`.
- **Статический анализ BSL** — поля: Наименование, Имя в .mcp.json, Назначение, URL,
  Порт, Подключение. Имя в .mcp.json по умолчанию `bsl_ls`; URL по умолчанию `localhost`;
  Назначение по умолчанию «Статический анализ кода на соответствие стандартам 1С».
  Подключение:
  ```json
  "bsl_ls": { "type": "http", "url": "http://localhost:8001/mcp" }
  ```
  Кнопка «Развернуть в Docker локально» — поднимает контейнер **только с BSL LS** (без кодовой
  базы, в отличие от `deps/mcp-bsl-lsp-bridge`). В корне проекта создаётся
  `.bsl-language-server.json` с настройками проверок. BSL LS проверяет лишь
  присланный код по настройкам и возвращает ошибки/предупреждения — доступа к кодовой
  базе у него нет.
- **Справка по платформе** — поля: Наименование, Имя в .mcp.json, Назначение, URL, Порт,
  Подключение. Имя в .mcp.json по умолчанию `1c_platform`; URL по умолчанию `localhost`;
  Назначение по умолчанию
  «Справочная информация по встроенным функциям, типам данных, методам и свойствам
  платформы». Подключение:
  ```json
  "1c_platform": { "type": "sse", "url": "http://localhost:8002/sse", "transport": "sse" }
  ```
  Кнопка «Развернуть в Docker локально» (см. `deps/docker_1c_sandbox/mcp-bsl-context`).
- **1С:Напарник** — поля: Наименование, Имя в .mcp.json, Назначение, URL, Порт, Токен,
  Подключение. Имя в .mcp.json по умолчанию `1c_naparnic`; URL по умолчанию `localhost`;
  Назначение по умолчанию
  «Объяснение логики кода, любые вопросы по информационно-технологическому
  сопровождению 1С». Подключение:
  ```json
  "1c_naparnic": { "type": "http", "url": "http://localhost:8003/mcp" }
  ```
  Кнопка «Развернуть в Docker локально» (см. `deps/docker_1c_sandbox/mcp-bsl-context`).
- **Индексированная кодовая база** — поля: Наименование, Имя в .mcp.json, Назначение,
  URL, Порт, Каталог кодовой базы (обязательный), Подключение. Имя в .mcp.json по
  умолчанию `code_index`; URL по умолчанию `localhost`; Назначение по умолчанию
  «Полнотекстовый поиск по функциям и классам,
  граф вызовов, паспорт объекта, смысловой поиск процедур по именам, синонимам и
  комментариям». Подключение:
  ```json
  "code_index": { "type": "http", "url": "http://localhost:8004/mcp" }
  ```
  Кнопка «Развернуть в Docker локально» (см. `deps/code-index-mcp`).

### Windows — требуемые доработки (docker-развёртывание MCP)

Приложение таргетит и Windows (`setup.ps1`/`run.ps1`). Непосредственно docker-часть
справочника MCP проверена на Linux; для Windows (Docker Desktop, WSL2-бэкенд, Linux-
контейнеры) нужны доработки — реализованное и остающееся:

- **`--network=host` при сборке** (СДЕЛАНО): `mcp_docker.build_cmd` добавляет
  `--network=host` только на Linux (`sys.platform`). На Docker Desktop host-сеть не
  поддерживается так же и не нужна (DNS в сборке работает) — флаг не добавляется.
- **Пути bind-монтирования томов** (ОСТАЁТСЯ): `launch_params` строит тома как
  `"<host>:<container>"`. На Windows хостовые пути (`C:\…`, обратные слэши, двоеточие
  диска) конфликтуют с разделителем `host:container` и форматом Docker Desktop.
  Нужна нормализация пути (слэши/драйв-леттер → `C:/…`) для `catalog_dir`
  (code-index), каталога состояния `.ai1c/mcp-state` с `daemon.toml` и пути платформы;
  плюс требование «расшарить» диск в Docker Desktop (File Sharing).
- **`1c-platform` — монтирование пути платформы** (ОСТАЁТСЯ): рецепт монтирует путь
  платформы «тем же путём» (`<path>:<path>:ro`) — это Linux-допущение. На Windows путь
  платформы (`C:\Program Files\1cv8\…`) нельзя использовать как внутренний путь
  Linux-контейнера: нужен фиксированный внутренний путь (например `/opt/1cv8`) и
  `ONEC_PLATFORM_PATH`, указывающий на него, при монтировании Windows-пути снаружи.
  Отдельно проверить, что серверу `mcp-bsl-context` достаточно файлов справки из
  каталога платформы (а не запуска самой платформы 1С).
- **Предпосылки среды** (ОСТАЁТСЯ, документация): Docker Desktop с включёнными Linux-
  контейнерами/WSL2; образы `bsl-ls`/`code-index`/`mcp-bsl-context` — Linux.

Остальные части Фазы 1 кроссплатформенны: бэкенд на Python/FastAPI (SQLite/Postgres
через `psycopg[binary]` — есть колёса под Windows), статический web, генерация
`.mcp.json`/конфигов, скачивание cfe. Отдельной Windows-доработки они не требуют.

## Фаза 2 — Бенчмарки

Оценка качества окружения: скрипт разворачивает тестовое окружение (целевое ИИ-
окружение + тестовая база с конфигурацией БСП), через claude cli подаёт набор
тестовых заданий оркестратору, таймаут (≈час на задание, срубание по таймауту), сбор
результатов и метрик процесса (какие MCP использованы, какие правила не применились,
почему долго ревью и т.п.), цикл улучшения окружения со сравнением прогонов.
Задания и способ проверки — за пользователем; мы делаем каркас.

## Фаза 3 — Удалённый доступ

Доступ к удалённым серверам: выполнение агентов/MCP по SSH или в Docker на удалённых
хостах (включая remote-PID/детач по SSH). В Фазе 0-1 — только `local`.
