# Интеграция с Telegram

Telegram-интеграция AgentMon даёт управление и наблюдение за агентскими
сессиями прямо из чата: уведомления о статусах задач и стеков, управление
стеком кнопками и просмотр артефактов выполненных этапов.

Интеграция **полностью опциональна**. Пока не задан токен
(`AGENTMON_TG_TOKEN`), ни бот, ни нотификатор не стартуют и на работу монитора
никак не влияют (`app/src/agentmon/telegram/runtime.py:30`,
`app/src/agentmon/__main__.py:44`).

Доставка апдейтов — **long-polling** в том же процессе FastAPI. Внешний
сервер, публичный HTTPS и webhook не нужны — работает из-за NAT как есть.

---

## 1. Создать бота и получить токен

1. В Telegram напишите [@BotFather](https://t.me/BotFather).
2. Команда `/newbot` → задайте имя и username бота.
3. BotFather пришлёт **токен** вида `123456789:AAH...` — это значение
   `AGENTMON_TG_TOKEN`.

> Токен — секрет. Он живёт в `.ai1c.env`, который не коммитится (см.
> `.gitignore`). В репозиторий попадает только `.ai1c.env.example`.

## 2. Узнать свой `chat_id`

Бот отвечает только чатам из allowlist (`AGENTMON_TG_CHAT_IDS`). Чтобы узнать
свой `chat_id`:

1. Откройте чат с ботом и отправьте ему любое сообщение (например `/start`).
2. Запросите апдейты через Bot API (подставьте свой токен):

   ```bash
   curl -s "https://api.telegram.org/bot<ТОКЕН>/getUpdates" | python -m json.tool
   ```

3. В ответе найдите `message.chat.id` — это и есть ваш `chat_id` (число,
   для личного чата — положительное; для группы — отрицательное).

Несколько получателей перечисляются через запятую.

## 3. Прописать конфигурацию в `.ai1c.env`

Откройте `.ai1c.env` (если его ещё нет — `cp .ai1c.env.example .ai1c.env`) и
заполните блок Telegram:

```ini
# Токен от @BotFather. Пусто/не задан → интеграция выключена.
AGENTMON_TG_TOKEN=123456789:AAH...

# Разрешённые chat_id через запятую (чужие чаты игнорируются).
AGENTMON_TG_CHAT_IDS=111111111,222222222

# База Telegram Bot API — обычно менять не нужно.
#AGENTMON_TG_API_BASE=https://api.telegram.org
```

Соответствие переменных и настроек — в `app/src/agentmon/config.py:21`.

## 4. Docker-режим: добавить `httpx`

Клиент бота работает на `httpx`. В host-режиме он уже стоит в окружении
монитора. В **docker-режиме монитора** (`AI1C_MONITOR_MODE=docker`) `httpx`
намеренно не входит в дефолтный образ — его нужно добавить явно:

```text
# app/requirements.txt
httpx
```

Затем пересобрать образ монитора. Подробнее — `docs/DEPLOY-DOCKER.md`
(раздел «Опциональный Telegram»). В host-режиме этот шаг не нужен.

## 5. Перезапустить и проверить

Перезапустите монитор (`python run.py` или пересобранный контейнер). При старте
с заданным токеном поднимаются две вещи рядом с диспетчером:

- long-poll цикл бота — отдельной asyncio-задачей;
- `TelegramNotifier.tick()` — встроен в `dispatch_loop` (период
  `DISPATCH_INTERVAL`, 3 с).

Проверка: отправьте боту `/start`. Авторизованный чат получит ответ
`AgentMon на связи. Команды: /projects /tasks /stacks`. Если ответа нет —
см. раздел «Диагностика».

## Что умеет бот

### Команды

| Команда     | Действие                                                             |
|-------------|----------------------------------------------------------------------|
| `/start`    | Приветствие и список команд.                                         |
| `/projects` | Список проектов (`#id name — path`).                                 |
| `/tasks`    | Задачи со статусом и текущим этапом; у каждой кнопка **📄 Отчёты**.   |
| `/stacks`   | Стеки со статусом и кнопками управления.                             |

### Управление стеком

Под каждым стеком в `/stacks` — две кнопки:

- **▶️ Запустить/Продолжить** → `POST /api/env/stacks/{id}/start`. Тот же путь,
  что кнопка в Web UI: выполненные элементы остаются `done`, диспетчер
  подхватывает следующий `pending` — это и есть «продолжение».
- **⏹ Остановить** → `POST /api/env/stacks/{id}/stop` (срубает текущий прогон).

### Отчёты по этапам

`/tasks` → **📄 Отчёты** у задачи → меню включённых этапов → тап по этапу →
бот присылает содержимое артефакта этапа (`ANALYZE.md`, `ARCHITECT.md`,
`TESTS.md`, `DEVELOP.md`, `TESTING.md`, `REVIEW.md`, `DOCS.md`). Длинный текст
режется на части по 4096 символов (лимит Telegram). Если артефакта нет или он
пуст — приходит «Артефакт этапа пуст или отсутствует».

### Уведомления (автоматически)

Нотификатор сравнивает текущие статусы с «уже уведомлёнными» и шлёт сообщение
всем `chat_id` из allowlist на интересующих переходах
(`app/src/agentmon/telegram/notifier.py`):

- **Задача**: `▶️ запущена` (`running`), `✅ завершена` (`done`),
  `❌ провалена` (`failed`), `⏸ ждёт пользователя (гейт)` (`awaiting_user`).
- **Стек**: `▶️ запущен`, `⏹ остановлен`, `✅ выполнен` (все элементы `done`),
  `🏁 завершён` (`idle`).

Переходы между этапами задачи **не** уведомляются — чтобы не шуметь.

Особенности:

- **Первый тик после включения — «молча»**: текущие статусы заносятся в
  `tg_notify_state` как baseline, без сообщений по уже существующим состояниям.
  Спама по старым задачам при первом запуске не будет.
- Отметка «уведомлено» (`last_status`) продвигается **только после успешной
  отправки** — рестарт монитора не теряет уведомление и не дублирует его.

### Замечания и одобрение гейта

Когда задача выходит на гейт «ожидает пользователя», приходит уведомление
`⏸ Задача ... ждёт пользователя (гейт)` с двумя inline-кнопками. Нотификатор
определяет гейт-этап (тот же критерий, что `overall_status`: включённый
гейтированный этап в статусе `done`, ещё не `approved`, после которого есть
`pending`-этап) и прикрепляет клавиатуру
(`app/src/agentmon/telegram/notifier.py`, `gate_stage_name` / `_gate_keyboard`):

- **✅ Одобрить** (`gate:ok:<task>:<stage>`) → `POST /api/env/tasks/{id}/approve`
  со `stage` — снимает гейт, задача идёт дальше.
- **✍️ Замечание** (`gate:note:<task>:<stage>`) → бот просит прислать текст
  ответом, сохраняет его в таблицу `task_feedback` **и** дозаписывает в
  `tasks/task#<id>/USER_FEEDBACK.md`, после чего **одобряет гейт**. Агент
  учитывает замечание на ближайшем этапе (правило
  `template/.claude/rules/user-feedback.md`).

Разбор нажатий — в `handlers.py` (`_route_callback`, ветка `gate`). Одобрить
гейт можно и из Web UI — путь тот же (`POST .../approve`).

> Замечание — это **текстовый комментарий**, который агент учтёт на следующей
> итерации, а не перезапись файла артефакта. Файлы артефактов бот не
> редактирует.

## Авторизация и безопасность

- Каждый апдейт сверяется с allowlist `AGENTMON_TG_CHAT_IDS`; сообщения и
  коллбэки из неразрешённых чатов **молча игнорируются**
  (`handlers.py:_authorized`). Мутации (старт/стоп стека, approve, замечание)
  доступны только авторизованным чатам.
- Токен и список `chat_id` держите в `.ai1c.env` (не коммитится). Не вставляйте
  токен в команды в общих логах/историях.
- Бот обращается к REST приложения по локальному адресу
  (`http://127.0.0.1:<PORT>`), наружу REST не публикуется.

## Как это устроено (кратко)

Пакет `app/src/agentmon/telegram/`:

- `client.py` — тонкий async-клиент Bot API на `httpx` (`getUpdates`,
  `sendMessage`, `answerCallbackQuery`, сборка inline-клавиатур).
- `bot.py` — long-poll цикл: тянет апдейты по `offset`, устойчив к сетевым
  сбоям (бэкофф 3 с, дедуп повторяющихся ошибок в логе).
- `handlers.py` — роутинг команд и callback-кнопок в существующие репозитории
  (`TaskRepo`, `StackRepo`, `ProjectRepo`), без дублирования логики.
- `notifier.py` — диффер статусов задач/стеков → уведомления.
- `reports.py` — чтение артефактов этапов и нарезка под лимит Telegram.
- `feedback.py` — приём замечаний (БД + зеркало в `USER_FEEDBACK.md`).
- `runtime.py` — сборка всего и обёртки REST/отправки; при пустом токене
  возвращает `None` (фича выключена).

Две служебные таблицы (идемпотентная миграция в `store/schema.py`):

- `tg_notify_state` — последнее уведомлённое состояние по каждой задаче/стеку.
- `task_feedback` — сохранённые замечания пользователя.

Полный дизайн: `docs/superpowers/specs/2026-10-17-telegram-integration-design.md`.

## Диагностика

| Симптом | Причина / проверка |
|---------|--------------------|
| Бот молчит на `/start` | Токен не задан или неверен; ваш `chat_id` не в `AGENTMON_TG_CHAT_IDS`; монитор не перезапущен после правки `.ai1c.env`. |
| `ModuleNotFoundError: httpx` в docker-режиме | Не добавлен `httpx` в `app/requirements.txt` и не пересобран образ (шаг 4). |
| Нет уведомлений по старым задачам | Это ожидаемо: первый тик после включения — baseline «молча». Уведомления идут по новым переходам статусов. |
| В логе «цикл бота упал» | Сетевая ошибка к `api.telegram.org`; бот сам повторяет с бэкофом. Полный traceback пишется один раз на каждый новый вид ошибки. |
| `getUpdates` не отдаёт `chat_id` | Сначала напишите боту сообщение, затем запрашивайте `getUpdates`. |

## Вне scope (осознанно не делаем)

- Перезапись файлов артефактов из Telegram.
- Webhook-доставка и публичный HTTPS/туннель.
- Роли/права сверх allowlist.
- Уведомления о переходах между этапами.
